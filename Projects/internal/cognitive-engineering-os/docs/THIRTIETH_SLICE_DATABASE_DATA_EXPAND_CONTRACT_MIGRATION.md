## Critic round: a Critical that undermined the method's entire purpose, plus two verbatim repeats from the immediately-prior slice

A `critic` subagent review found the core ordering invariant itself was sound (no off-by-one, order-independent, correctly rejects every genuine skip) and the citation work was the best of the session -- but found 1 Critical and 4 Major, three of which were exact repeats of findings the immediately-prior `database_data.reconciliation` slice's own critic round had already caught, fixed, and left named regression tests for:

1. **Critical, fixed** -- the first draft's ONLY invariant was presence-based (which stage_ids exist), never comparing `completed_at` across stages. A record could therefore record `reconciliation` completed 2026-09-30 and `contract_old_schema` (which destroys the rollback path) completed 2026-08-09 -- the schema physically destroyed BEFORE reconciliation ever ran -- and pass the builder, both gates, and the schema, directly falsifying the method's own purpose line ("completed... in order"). Fixed by requiring `completed_at` to be a real, parseable ISO-8601 timestamp (removing the first draft's free-form-string design, which is exactly what made the hole possible) and enforcing non-decreasing order across stages sorted by canonical index, independently at both the builder and the gate.
2. **Major, fixed (verbatim repeat)** -- an unhashable `stage_id` (a list/dict) escaped as a raw `TypeError` instead of failing closed, at three call sites -- the identical bug class `database_data.reconciliation`'s own critic round had fixed one file over, with a named regression test the review found could have been consulted before writing this module. Fixed with an `isinstance` guard before every `in _STAGE_INDEX` check.
3. **Major, fixed (verbatim repeat)** -- hand-built stage dicts were stored verbatim (aliased, not rebuilt), letting an attacker-controlled extra field (e.g. a self-declared `status: pending` marker) survive into a record certified as fully completed, and letting a caller mutate an already-constructed record's own stages after the fact. Fixed by rebuilding every stage from known fields only -- the identical fix `database_data.reconciliation`'s own critic round had already established.
4. **Major, fixed (verbatim repeat)** -- three gate tests asserted only `status == "FAIL"` with no evidence pinning; the critic ran a real mutation (deleting the gate's unknown-stage guard) and proved all three stayed green, unable to distinguish which guard actually fired. Fixed by pinning `evidence[0]["reason"]` and the specific offending id/pair on every gate test.
5. **Major, fixed** -- the contract claimed a `contract-backlog.yaml` registration that did not exist (the identical Minor the prior slice's own critic round had caught in that slice, now recurring one contract later). Fixed by adding the `twentyeighth_concrete_entry`.

Additional Minor findings fixed: `evidence_ref` was completely unvalidated (empty string, non-string) at every layer; `_non_contiguous_gaps` could silently return "no gap" on malformed duplicate input if ever called directly (mitigated by changing its parameter type to `frozenset[str]`, making the precondition structurally unforgeable rather than merely runtime-checked); `modules/database_data/__init__.py`'s own docstring was stale by two family members (missing `reconciliation` AND this slice -- fixed for both in one edit); no slice doc existed (this file).

The broader lesson this round adds: "I explicitly tried to apply every prior lesson" (this slice's own first-draft docstring) is not a substitute for grepping the immediately-prior slice's own regression-test docstrings and WORKLOG Minor list BEFORE writing, not after being caught repeating them. Three of five Major findings here were mechanically avoidable that way.
