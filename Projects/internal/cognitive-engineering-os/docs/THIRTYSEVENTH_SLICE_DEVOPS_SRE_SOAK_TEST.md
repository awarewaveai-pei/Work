## What was built

Atlas gives this method one citation: F19's Soak Test row (L855: purpose "驗證長時間穩定", usage "持續負載→memory/resource leak→degradation", benefit "找慢性問題"). The defining difference from its two immediate siblings: `load_test` compares two measurements at *different* load levels; `stress_test` escalates across an *increasing* ladder; this method holds load **perfectly constant** and instead varies **time** -- a series of samples searching for drift only a real duration can reveal.

Six invariants: (1) a time-ordered series of >=3 samples; (2) with strictly increasing `elapsed_minutes`; (3) every sample held at the one declared `sustained_load_rps` (the opposite discipline from `stress_test`'s escalating ladder); (4) uniform resource sets across the whole series; (5) caller-supplied `degradation_thresholds` re-verified by the gate (the capacity_model/load_test/stress_test lesson applied from the first draft); (6) a COMPUTED `degradation` verdict comparing the first sample against the last (deliberately not an invented trend/regression statistic -- see compilation_decisions), fully derived with no override.

## Critic round: `warn` -- logic sound under a 4,000-series oracle, but the Decimal fix and two mirror-image boundaries were unpinned

A `critic` subagent review (45 runtime mutations, a temp spec-root schema probe, and an independently written oracle over 4,000 enumerated series using exact `Fraction` arithmetic) found the core sound: zero builder-vs-oracle mismatches, zero gate escapes on any of 4,000 tampered `overall_degraded` flips, every builder `raise` traced to a gate branch on the same shared predicate (including the gate re-validating `degradation_thresholds` **before** trusting a stored `degradation`, the capacity_model/load_test/stress_test lesson confirmed genuinely applied), the cross-file `$ref` reuse confirmed to both resolve and enforce inside the sample wrapper, and no invented rule. Verdict `warn` for three Major findings, all fixed:

1. **Major, fixed** -- the Decimal fix (disclosed in this doc's first draft) covers all three arithmetic sites in code, but only the resource-utilization site had a boundary test able to actually distinguish `Decimal` from raw `float` subtraction; reverting *just* the latency or *just* the error-rate line to raw subtraction survived the whole suite. Two tests added mirroring the existing one (`100.7->100.9` vs a `0.2` latency budget; `0.7->0.9` vs a `0.2` error-rate budget), each proving the exact boundary and the one-cent-over case.
2. **Major, fixed** -- `_measurement_is_valid`'s exact-key-set rejection had no test at the builder or gate layer (only via `SchemaContracts.validate`); weakening it to a subset check survived both. A builder test and a gate test added for an extra key inside a sample's own `measurement`.
3. **Major, fixed** -- threshold range tests covered only 2 of 4 field x direction combinations (the same mirror-image-boundary class `devops_sre.stress_test`'s own critic round already caught once, on a different axis): `resource_increase_max > 1` and `error_rate_increase_max < 0` were both unpinned. Two tests added.

Minor, all fixed: an empty `resource_utilization` map had no builder-level test (would silently no-op the entire "memory/resource leak" half of the formula); the documented `bool`-exclusion guard had zero test coverage; the due-diligence enumeration understated the grep results (the jurisdiction "auto_degrade" family and a stale Phase-0 research-snapshot duplicate entry are now named explicitly); this doc's own "Six invariants" line listed five items (now split); `detect_degradation`'s own resource-key-lookup direction is an equivalent mutant with an undisclosed bare-`KeyError` path if its own precondition were ever violated directly (now disclosed in the compute module's own docstring -- unreachable through the gate today, since resource-set uniformity is checked first).

## Honest limits

No method-inventory.yaml machine_id row (`OQ-SOAKTEST-1`). `degradation` compares only the first and last sample -- a leak that spiked mid-soak and partially recovered by the last sample would be under-reported; intermediate samples are recorded but not consumed by the verdict (`OQ-SOAKTEST-2`, disclosed, not silent). F19 will be complete once `devops_sre.rto_rpo` is built (`OQ-SOAKTEST-3`). No soft link to `devops_sre.capacity_model` for a discovered leak to motivate a coefficient revision (`OQ-SOAKTEST-4`). Own id prefix, `version` type, and top-level key set are schema-layer only / unconstrained; `generated_by_method` can be mislabelled undetected -- the same family convention prior slices disclosed.
