## What was built

Atlas gives this method one citation: F19's Stress Test row (L854: purpose "找系統破壞點", usage "超過預期負載→觀察 cliff/recovery", benefit "了解安全餘量"). **Checked and confirmed distinct from F12's near-identically-named "Stress Testing" row (L652)** -- the exact collision Phase-0's own `verified-findings.yaml:1052` flagged two Method Atlas passes ago. Neither carried a machine ID before this contract; `devops_sre.stress_test` now disambiguates one side.

Five invariants: an escalating ladder of >=2 load measurements with strictly increasing load and uniform resource sets; at least one step strictly exceeding `expected_load_rps`; caller-supplied `breaking_thresholds` re-verified by the gate (the capacity_model/load_test lesson applied from the first draft); a COMPUTED `breaking_point` (first breaching step, or `null` -- an honest "no cliff found" outcome); and a `recovery` observation REQUIRED iff a breaking point was found, FORBIDDEN otherwise, with its own reduced load strictly below the breaking load and its own `recovered` fully derived, no override.

## Critic round: `warn` -- logic sound under 349,440 oracle cases, but the untested-boundary and half-enforced-schema classes both recurred

A `critic` subagent review (50 runtime mutations x 62 tests, an independently written oracle over 349,440 enumerated (ladder x thresholds x recovery) cases, and a direct `jsonschema` probe of the schema's own `if/then/else`) found the core sound: zero oracle escapes, zero false refusals, zero gate/builder disagreements; every builder `raise` traced to a gate branch calling the identical shared function; the cross-file `#/$defs/load_measurement` reuse confirmed to both resolve and enforce, with the runtime's own reimplemented `_measurement_is_valid` predicate verified field-by-field consistent with it; no invented rule. Verdict `warn` for four Major findings, all fixed:

1. **Major, fixed** -- the FIRST-breach-by-order semantics (this method's entire meaning) had no test with two breaching steps, so a mutation that kept the LAST breach instead of the first survived, and a mutation that re-sorted the ladder by `load_rps` before searching (exactly what `compilation_decisions #3` forbids) also survived. Two tests added: a two-breach ladder pinning the first index, and a deliberately non-monotonic ladder pinning search-by-caller-order.
2. **Major, fixed** -- `_derive_recovered`'s `AND` survived being flipped to `OR`, because both existing `recovered:false` fixtures breached both metrics at once (never just one). A latency-ok/error-bad and an error-ok/latency-bad case now each pin `recovered:false` and refuse a caller asserting `true`.
3. **Major, fixed** -- the inclusive `<=` boundary on `recovered` was unpinned (only its mirror-image breaking-point boundary had a test). Added a recovery measurement landing exactly on both thresholds, asserting `recovered:true`.
4. **Major, fixed** -- the schema's `if/then/else` `else` branch used `properties` alone, which JSON Schema never enforces against an ABSENT key -- a record with a real breaking point and `recovery` simply omitted (not null) passed the schema layer undetected (the runtime gate still caught it, so no record could actually escape both layers). Added `required: [recovery]` to both branches and a key-absent regression test.

Minor, all fixed: three defensive predicate constraints (bool `load_rps`, empty utilization map, `load_rps:0` acceptance) had no dedicated test; `breaking_point.load_rps`'s `exclusiveMinimum:0` was inconsistent with the reused measurement's own `minimum:0` (relaxed to match); "ten shared predicates" imprecisely counted an imported compute function as a predicate (corrected to "nine... plus the shared `find_breaking_point`"); the drift-chain list had silently dropped "RTO/RPO comparison" while keeping it in the ordinal count (restored); `generated_by_method`'s undisclosed mislabel risk (family-wide, first disclosed by `load_test`'s own critic round) was missing from this doc's own Honest limits (re-added below).
