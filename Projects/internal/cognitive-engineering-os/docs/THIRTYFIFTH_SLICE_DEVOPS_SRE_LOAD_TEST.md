## Critic round: `warn` -- the logic held, the claims and the proofs did not

A `critic` subagent review (36 runtime mutations x 66 tests, 17 schema-layer deletions against a temp spec-root copy, an independently written oracle over 705,600 enumerated (baseline, target, acceptance) shapes, and a float-edge sweep) found the core sound: **zero oracle disagreements**, every builder `raise` traced to a gate branch calling the same shared function, `#/$defs/load_measurement` proven to resolve at both `$ref` sites, the Decimal benefit proven real (`0.3/0.1` is `2.9999999999999996` in raw float), and no invented rule. Verdict `warn` for three Major findings of the repeat classes this session already named:

1. **Major, fixed** -- a false numeric claim: this module called itself the "ninth" reuse of the shared `genuine_compute` gate; it is the eighth, because `capacity_model`'s own docstring had called itself the eighth while listing six predecessors (`computation.monte_carlo` deliberately does not reuse the gate). Both corrected in this commit -- the upstream error, not just the inherited one.
2. **Major, fixed** -- 17 schema constraints survived deletion with a green suite (only 4 were pinned). Six more high-value pins added (`propertyNames`, top-level `required`, `engine` const, `acceptance` `additionalProperties`, `error_rate_delta` bounds, `computation_provenance_ref` pattern). The remaining unpinned constraints are the family-wide fixture gap (29 fixture files for 36 typed objects) -- disclosed, not closed here.
3. **Major, fixed** -- the overflow guard was reachable through the public API with predicate-valid, schema-valid inputs (`5e-324` baseline p95 vs `1.7e308` target p95 → `inf` ratio) and completely untested; removing it, the `DecimalException` handler, or the gate's `except` all survived. Three tests added (compute, builder, gate).

Minor, each fixed: the honest-limits line claimed the top-level key set was "schema-layer only" when no layer constrains it (reworded, below); `generated_by_method` can be mislabelled and no layer notices (disclosed below, family-wide); "eight shared predicates" matched no real count (now "nine boolean predicates plus two"); two nearest typed objects (`quality-attribute-scenario`, `sli-slo-set`) were missing from the neighbour list; `policy-inventory.yaml:267` is `kind: gate`, not "a policy item"; the stray `agency-os/` hook trees (already in `TASKS.md`); and this doc's own "pending" placeholders.

The lesson this round adds: an ordinal copied from a sibling docstring is a claim, and claims inherit errors -- the only defense is counting again. And a guard that only fires on inputs no test constructs is indistinguishable from dead code until someone constructs them.
