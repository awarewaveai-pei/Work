## Phase 1 scope -- CODE COMPLETE + DEPLOYED 2026-09-12

Live at **https://cognitive.aware-wave.com** (ks-aw-01, container `cognitive-os-api`, joins `lobster-net`). Items 1-5 below are built, tested, critic-reviewed, and deployed (see WORKLOG 2026-09-12 "Cognitive OS Phase 1" + deploy-scaffolding + deploy-execution entries).

1. **Domain** -- DONE. `specs/domain/workspace.schema.yaml` + `specs/domain/identity.schema.yaml` (new), `ai_lego/core/domain/{workspace,identity}.py` (builders). Real `Tenant` + `Workspace` + `Identity` rows persisted in SQLite (`ai_lego/platform/identity/store.py`) -- not mocked, not hardcoded. `python -m ai_lego.apps.cli.bootstrap_phase1_tenant --email ... ` creates the real (non-synthetic) Phase 1 tenant. `encryption_root_key_ref` is a disclosed local-dev placeholder (no real KMS yet -- deferred to Phase 2/3 when real customer data exists, see `.foundry/risk-classification.json`).
2. **Entitlement seam** -- DONE. `ai_lego/platform/entitlement/check.py`'s `check_entitlement(store, tenant_id, capability_id) -> bool`. Phase 1: grants iff the tenant exists and is active; every check is audited (`entitlement_audit` table) regardless of outcome, so Phase 2 only needs to replace the grant *logic*, never add auditing that was missing.
3. **API** -- DONE (`ai_lego/apps/api/main.py` + `dispatch.py`). `GET /methods`, `GET /methods/{id}`, `POST /auth/login`, `POST /auth/logout`, `POST /methods/{id}/invoke`, `GET /methods/{id}/demo`, `GET /recipes`, `GET /recipes/{id}/plan`, `POST /recipes/{id}/run`. Dispatch is generic (introspection-based, not a hand-maintained per-method adapter table). **`GET /` -- browser dashboard**: login, method browser, live method JSON form, ACTIVE Recipe list, Recipe source JSON and Run Recipe. Recipe execution uses compiled IR, explicit bindings, MethodCatalog, CapabilityCatalog, explicit adapter registry, entitlement checks, atomic journal/resume and per-step gates; deterministic offline `literature_search`, Trusted Compute `run_statistics`, and side-effect-free `artifact.generate_research_paper` adapters are registered, while missing capability adapters and missing bindings fail closed. CORS is default-off; `COGNITIVE_OS_CORS_ORIGINS` accepts an explicit comma-separated HTTP(S) origin allowlist only. Catalog-derived text uses `textContent`/`createElement`, not interpolated `innerHTML`.
4. **Auth** -- DONE for Phase 1 login/session. Real Identity + PBKDF2-HMAC-SHA256 password hashing (600,000 iterations, OWASP 2023+ floor), real server-side session tokens (256-bit, revocable, 12h TTL), `Secure`/`HttpOnly`/`SameSite=Strict` cookies. Password-reset core now has one-hour, single-use, SHA-256-digested tokens; replacing a password atomically consumes the token and revokes all existing sessions. An external delivery adapter is intentionally not configured yet, so no API claims self-service reset is available and no raw token is logged or persisted. A critic pass (2026-09-12, Standard tier, auth/crypto rigor) found 0 Critical, 1 Major (a timing side-channel in `authenticate()` letting an attacker distinguish "no such email" from "wrong password" by response latency -- ~182ms/730x gap measured directly) -- fixed same day with a constant-cost dummy-hash branch, regression-tested by actually measuring timing (`tests/unit/test_authenticate_timing.py`), not just asserting return values. 1 Minor (bootstrap CLI's `--password` argv flag can leak into shell history -- already defaulted to a `getpass` prompt instead; added an explicit stderr warning when the flag is used anyway). Verified clean: SQL injection (all queries parameterized), cross-tenant leakage (same email+password cannot authenticate against a different real tenant), the generic dispatch/demo endpoints cannot execute anything beyond the 249 real, pre-scanned Method Atlas contracts (live-exploit-tested with path-traversal/injection-shaped `method_id` payloads, all correctly 404).
5. **Deploy** -- DONE 2026-09-12. `ks-aw-01`, Docker Compose (`docker-compose.yml`, joins `lobster-net` externally, precedent: `ziwei-doushu`'s `oracle-web`), `deploy/deploy.sh` 6-item checklist (test gate / healthcheck / smoke / rollback / notification / typecheck) per `agency-os/AGENTS.md` section 0 -- critic-reviewed (1 Critical + 3 Major found and fixed pre-deploy, see WORKLOG). Two-layer nginx wired (`lobster-nginx` container + host `sg-stack.aware-wave.com` vhost), TLS cert SAN expanded via `certbot --expand` (valid through 2026-12-11), Cloudflare DNS A record (proxied). Domain: `cognitive.aware-wave.com`. Real Phase 1 tenant bootstrapped via `bootstrap_phase1_tenant.py` inside the running container (matches the volume-backed `.runtime/identity.sqlite3` exactly).

Verification evidence: 73 tests pass locally + again on `ks-aw-01` inside `deploy.sh`'s test-gate (`tests/unit/test_{workspace_domain,identity_domain,identity_store,entitlement_check,api_dispatch,api_main,authenticate_timing}.py`); a real `uvicorn` server was started locally pre-deploy and exercised end-to-end with real `curl` requests (login -> invoke -> demo -> logout), not only the FastAPI `TestClient`; corpus-wide `pytest tests/unit` shows zero regressions against the pre-existing 245+ Method Atlas tests. ## 2026-09-14 runtime expansion

- Dashboard Recipe input now includes a binding-derived field editor for ordinary and JSON-valued Source fields, while retaining the raw JSON editor as the canonical escape hatch; it does not invent domain types outside the Method contracts.
- `life-decision-v1`: frame → SWOT → weighted decision matrix.
- `edd-research-evidence-v1`: assumption mapping → evidence matrix → Toulmin argument.
- `art-therapy-creative-reflection-v1`: random stimulus → mind map; non-diagnostic, no automated clinical inference.
- `art-therapy-project-ideation-v1`: problem framing → random stimulus → mind map; a three-step non-diagnostic project-ideation chain that preserves the `NOT_YET_SCREENED` boundary.
- `business-foundation-v1`: SWOT → TOWS (consumes the preceding SWOT output) → Porter Five Forces → Business Model Canvas; deliberately stops before finance/simulation/KPI/proposal publication.
- `business-feasibility-review-v1`: caller-supplied break-even inputs → genuine-compute NPV; a bounded numeric feasibility review, not the missing Finance Domain Pack or an investment recommendation.
- `business-planning-feasibility-v1`: SWOT → TOWS → Porter → BMC → Scenario → Risk → TCO → Unit Economics → Break-even → NPV; a ten-step pre-proposal chain with explicit inputs, real numeric computation, and human-review boundaries.
- F14 feasibility/economics is now 9/9 implemented Atlas methods (TELOS, cost-benefit, cost-effectiveness, TCO, unit economics, break-even, NPV, IRR, real options), each with a contract and tests; this remains distinct from the unbuilt `finance.financial_assumptions` Finance Domain Pack node.
- Gate dispatch now binds runner arguments by signature and workflow context, so cross-method gates such as TOWS are evaluated without positional assumptions.
- Recipe planning now reports method-dispatch, capability-adapter, and binding readiness separately from contract resolution; a contract-complete but undispatchable method, unregistered required capability, or unbound node is visibly `BLOCKED`, not presented as executable.
- Method-node bindings are also checked against the live builder signature during planning and again before run; unknown, malformed, or missing required arguments produce `METHOD_BINDING_BLOCKED`/`WORKFLOW_METHOD_BINDINGS_INVALID` instead of a late builder `TypeError`.
- Recipe compilation validates the emitted Workflow IR against the canonical `workflow-ir.schema.yaml` at the compiler boundary; the read-only schema registry is cached per spec root so this invariant applies to CLI and API callers without repeated full reloads.
- The compiler also validates Workflow dataflow: duplicate output labels, unknown `outputs.<label>` references, and unknown/forward `steps.<index>` references fail before a run or journal can start; nested fields remain supported.
- Runtime projections apply the same ordering guard to selected nodes; outputs from omitted upstream nodes are treated only as explicit external boundary inputs, never as silently reordered internal dependencies. Every ACTIVE Recipe is covered by an inventory-wide compile regression.
- Projection label aliases rewrite downstream `outputs.<label>` bindings within the selected subgraph before validation, preventing a renamed producer from leaving stale consumers behind.
- Projection runtime overrides are authoritative: inherited dataflow paths are rewritten before explicit `input`/`bindings` are applied, so a vertical slice can replace an omitted producer boundary without resolving stale bindings from the full Recipe.
- API run responses expose an opaque `workflow-journal://` reference rather than an absolute host filesystem path; journal storage remains server-internal and tenant-namespaced.
- API workflow responses expose execution evidence (`steps`/`outputs`/`gates`) through a response projection and omit the caller's raw `source`; the full source remains available only to the in-process executor and fingerprinted journal lifecycle.
- API journal custody accepts `COGNITIVE_OS_JOURNAL_KEY_MODE=external` only when a process-startup-injected `JOURNAL_KEY_RESOLVER(tenant_id, purpose)` returns a validated 32-byte key; absent or failed injection blocks without local fallback.
- Recipe runs now preflight every declared initial `source.*` binding before creating a journal; missing paths return a structured `WORKFLOW_SOURCE_FIELDS_MISSING` 400, while downstream `outputs.*` bindings remain runtime-resolved.
- Shared runtime now supports explicit context bindings, registered capability adapters, durable journal/resume, caller-selected journal projection, injected `JournalKeyProvider` and AES-256-GCM journal protectors, tenant-scoped CAS storage, canonical `JsonArtifactStore` with hash verification, ownership-and-reference-checked object deletion, policy-gated deletion orchestration using the canonical EC §31 10-step record, and a tenant-scoped derived-artifact cache keyed by source hash plus adapter version. Protected journals keep checkpoint outputs only inside encrypted context (step ledger stores status/contract metadata without a second plaintext output copy); CAS reads enforce tenant ownership and ciphertext hash integrity, and destructive deletion verifies the reference before unlinking. `CachedTranscriber` reuses verified transcript derivations while excluding local audio paths from cached payloads. API source-bearing runs default to projection-only; an explicit local-dev key provider plus injected 32-byte key enables the local CAS protector, and `CONFIDENTIAL`/`RESTRICTED` sources are rejected without protection. Production KMS/HSM key custody, crypto-shred and retention policy are still required before external or clinical data is accepted. The 7-step qualitative Research Recipe now runs as an API MVP when supplied a normalized, provenance-bearing Transcript plus reviewed coding inputs; its transcription mode is explicitly `PRE_TRANSCRIBED_INPUT` and makes no raw-media/STT claim. Production transcription/storage, external literature providers, 31 new art-therapy methods, and Business Planning's finance/computation chain remain open.
