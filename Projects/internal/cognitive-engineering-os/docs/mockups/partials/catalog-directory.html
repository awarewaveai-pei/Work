SIPOC（供應者-輸入-流程-輸出-顧客）Suppliers-Inputs-Process-Outputs-Customers
用五個欄位——供應者、輸入、流程、輸出、顧客——完整框定一個流程。想在深入細部流程對照之前，先界定流程範圍跟關鍵因素時用。
主體模型模擬Agent-Based Modeling
從個別主體各自的規則出發，在共享環境中跑多次模擬，觀察整體行為如何浮現。系統整體行為沒辦法單從某一個主體的規則推算出來、必須真的跑模擬才看得到湧現結果時用。
事件樹分析Event Tree
從單一起始事件出發，依序分岔每個屏障成功／失敗的結果，推演出完整的後果分支。想看一個觸發事件的所有可能後果時用，是 Fault Tree 反向分析的正向對照版。
五個為什麼Five Whys
針對每個答案反覆追問「為什麼」，從表面症狀一路往下鑽到根本原因，形成單一因果鏈。想用輕量、快速的方式往下鑽、且問題單純到一條線就能講清楚時用。
冰山模型Iceberg Model
把一個表面事件逐層往下挖——重複發生的型態、系統性結構、支撐這一切的心智模式，一次一層。想避免只針對單一事件反應，而是找出產生一整類類似事件的深層結構時用。
凱普納-崔果問題分析Kepner-Tregoe Problem Specification
用 What/Where/When/Extent 四個維度的 2x4「是／不是」表格框定問題，再找出能解釋這個型態的特徵與變化。覺得 Five Whys 太主觀、想先做結構化、證據導向的問題界定時用。
反事實推理Counterfactual Reasoning
比較「實際發生的」跟「假設沒介入會怎樣」，建立明確的因果比較基準。想確認一個介入措施是否真的有效時用。
合成控制法Synthetic Control
記錄一個用其他個案加權組合出「虛擬對照組」的研究設計（只記錄設計）。只有一個處理個案、找不到真實對照組時用。
因果回饋圖Causal Loop Diagram
畫出變數間的回饋迴路，並根據連結的正負極性獨立重新計算每個迴路是「增強」還是「平衡」，而不是相信使用者自己貼的標籤。想理解一個系統為什麼會不斷放大或自我修正某個趨勢，而不只是看到趨勢本身時用。
因果圖 DAGCausal DAG
用有向圖畫出變數之間的因果關係，找出干擾變數與正確的因果路徑。想釐清「到底是誰影響誰」、避免把相關性當因果時用。
場域分析（推力與阻力分析）Force Field Analysis
列出推動一項改變的力量跟阻礙它的力量，各自評分 1-5，並自動算出淨力。想一眼看出目前一項改變究竟是推力比較大還是阻力比較大時用。
存量與流量圖Stock & Flow
把累積量（存量）跟填入／流出的速率（流量）建模出來，要求每個存量至少被一個真實流量影響。想理解庫存、預算、人口等隨時間變化的動態行為，而靜態快照看不出來時用。
屏障分析Barrier Analysis
追蹤危害→目標→屏障→失效，找出哪個控制措施沒能阻止事件，且設計上完全沒有歸咎個人的欄位。出事後想聚焦系統控制、不是怪人時用。
工具變數法 IVInstrumental Variables
記錄一個用工具變數處理內生性問題的研究設計（只記錄設計，不跑迴歸）。懷疑變數間有雙向因果時，先把設計寫清楚用。
差異中的差異法 DiDDifference-in-Differences
記錄一個「處理組 vs 對照組、介入前 vs 介入後」的研究設計（只記錄設計，不跑迴歸）。想評估政策效果，先把研究設計寫清楚時用。
改變理論Theory of Change
用「投入→活動→產出→短期成果→長期成果→影響」六階段，串起假設、證據、指標、風險。做長期專案或社會影響評估規劃時用。
故障樹分析Fault Tree
從頂端事件（已經發生的故障）出發，透過 AND/OR 邏輯閘往回推到基本事件。想找出會導致某個已知壞結果的所有根本失效組合時用。
斷點迴歸設計 RDDRegression Discontinuity Design
記錄一個利用「切點附近樣本」估計因果效果的研究設計（只記錄設計）。有明確資格門檻可做自然實驗時用。
柏拉圖分析（80/20 法則）Pareto Analysis
依發生頻率或影響程度排序原因，找出佔多數效果（約 80%）的少數關鍵原因（約 20%）。有很多候選原因但時間有限，需要決定先修哪個時用。
槓桿點分析Leverage Point Analysis
把一個介入點分類到 Donella Meadows 五層槓桿點階層之一——參數、回饋迴路、規則、目標、典範——並自動算出其深度等級。想比較不同介入方案的槓桿深度時用，因為淺層修改（參數）通常解決不了系統性問題。
流程圖Flowchart
把工作流程畫成連續步驟，只有一個起點、至少一個終點，每個決策點至少分岔出兩條有條件的路徑。想找出一個反覆出現的困擾歷程實際卡在哪一步，直接把步驟畫出來看時用。
生活系統圖Life System Mapping
畫出一個人生活中的各個子系統（家庭、工作、人際關係等），以及彼此之間的影響方向。想看出不同生活面向如何互相影響，而不是把每個領域分開來看時用。
系統原型Systems Archetypes
把觀察到的情況對照到 10 種已知系統原型（如成長的極限、飲鴆止渴）的封閉清單，每個判定都要求引用實際觀察到的症狀作為證據。想辨認出一個熟悉的系統性陷阱、而不是每次都從零重新診斷時用。
蝴蝶結分析Bow-Tie Analysis
左邊威脅（預防）、右邊後果（緩解），中間是頂端事件——每個控制措施都要有真正的負責人跟測試方式。想同時管理同一個風險的預防跟復原時用。
變更分析Change Analysis
比對故障前後狀態，跟變更清單做關聯——關聯不等於因果，這是用來縮小範圍，不是下結論。事故發生後，想快速列出「最近改了什麼」時用。
豐富圖像Rich Picture
在一個混亂、還套不進正式模型的情境中，自由地畫出角色、流程、衝突，並要求每個記錄的議題都能追溯回真實角色。想對複雜情境先做一次非正式的初步梳理，之後再套進更嚴謹的框架時用。
過程追蹤法Process Tracing
用機制證據（不只是統計相關）逐步檢查一條因果鏈是否成立。樣本數很小、無法做統計因果推論時用。
邏輯模型Logic Model
用「投入→活動→產出→短期成果→長期成果」固定五階段，結構化描述一個專案／方案。做專案評估或跟 KPI 對齊時用。
隨時間變化行為圖 BOTBehavior Over Time Graph
把一個追蹤的變數，依嚴格時間順序畫成一條序列，不接受單一個點或順序錯亂的資料。想強迫分析聚焦在「隨時間變化」，而不是只看單一時間點的快照時用。
隨機對照試驗 RCTRandomized Controlled Trial
記錄一個隨機分派、把樣本分成處理組／對照組的研究設計（只記錄設計，不跑統計分析）。想用最嚴謹方式驗證因果，先把設計寫清楚用。
魚骨圖（石川圖）Fishbone / Ishikawa Diagram
把一個問題的候選原因，依標準類別（人、流程、設備、物料、環境）分支排列在一條主幹上。想先廣泛腦力激盪、分類原因，再用 Five Whys 或 Pareto 收斂時用。
幾個選項，選哪一個？14 個
ICE 評分法Impact x Confidence x Ease Scoring
用同一個尺度為每個選項打影響力、信心度、容易度三個分數，快速粗排優先序。想快速排序一大堆候選項目時用。
MoSCoW 優先分級MoSCoW Method
把一堆項目分到「必須／應該／可以／不做」四類，建立明確的「不做清單」。要鎖定一個版本的範圍時用。
RICE 優先排序法RICE Prioritization
用「觸及人數×影響力×信心度÷努力程度」為產品待辦事項排序。想讓「努力程度」用除的方式真正拉低分數時用。
加權最短工作優先法 WSJFWeighted Shortest Job First
用「延遲成本÷工作量」排序一個投資組合，凸顯「拖越久越貴」的項目。在敏捷投資組合裡想依延遲成本（不只是工作量）排序時用。
加權決策矩陣Weighted Decision Matrix
用選項×準則×權重、在同一個評分尺度上打分（不像 MCDA 需要逐項正規化，更簡單）。所有準則能共用同一個評分尺度時，用它做直接的加權比較。
卡諾模型Kano Model
依滿意度曲線形狀（不只是票數）把功能分類成基本／表現／驚喜型。想判斷哪些功能真的對使用者重要時用。
多準則決策分析 MCDAMulti-Criteria Decision Analysis
用多個自訂加權準則為選項打分（選項→準則→權重→正規化→評分→敏感度）。有多個選項、多個評分標準時，用它算出有依據的排名建議。
層級分析法 AHPAnalytic Hierarchy Process
建立目標→準則的層級結構，用兩兩比較推導出權重，並檢查比較是否前後一致。要做嚴謹的多準則決策、連權重本身都要站得住腳時用。
影響力-努力矩陣Impact-Effort Matrix
用兩個固定軸（影響力、努力程度）把選項分到四個象限（快贏／大賭注／填補／坑）。只需要兩個維度、想快速視覺化排優先序時用。
期望值Expected Value
把機率乘以結果加總，算出單一期望值。要在動用完整決策樹或蒙地卡羅之前，先算一個簡單基準時用。
柏拉圖前緣Pareto Frontier
找出「沒有其他選項在每個目標上都更好」的一組方案（多目標優勢分析）——跟單一維度的 80/20 不同。同時要優化兩個以上互相拉扯的目標時用。
決策樹Decision Tree
用決策節點與機率節點（含機率與報酬）分支呈現不確定性。多階段決策、後面選擇取決於前面隨機結果時用。
艾森豪矩陣Eisenhower Matrix
用「緊急程度 x 重要程度」對照你自訂的門檻，把每項任務分到「立即做／排程／委派／刪除」四象限。想快速對一份任務清單做第一輪篩選時用。
逼近理想解排序法 TOPSISTechnique for Order of Preference by Similarity to Ideal Solution
用選項跟理想解／最差解的距離排序，不是用加權總分。想要跟 MCDA 加權總分不同的排序邏輯時用。
問題到底是什麼？24 個
5W1H 問題輪廓5W1H Problem Profile
用 Who/What/When/Where/Why/How 快速建立模糊問題的輪廓，明確標出哪些面向還沒答案。資訊不足、連問題都還定義不清楚時，最開始用它。
GROW 模型GROW Model
設定目標與具體行動策略。非診斷工具。
MECE 檢查MECE Check
檢查一組分類是否互斥且完整，找出重疊與遺漏。對任何已經拆好的分類結構做健檢時用。
OKR 目標關鍵成果Objectives and Key Results
把方向（O）跟 2-5 個可衡量成果（KR）分開，各自指定負責人與檢視頻率。團隊／季度目標設定，避免只追工作量時用。
SMART 目標SMART Goal
用五個固定標準（明確、可衡量、可達成、相關、有時限）精煉一個已經說出口的目標。在目標陳述之後、覺得目標還不夠具體時用。
價值觀排序Value Sorting
釐清個人或團隊的核心價值。非診斷工具。
功能分析系統技術 FASTFunction Analysis System Technique
往左問 Why、往右問 How，建出功能鏈。想找出冗餘功能與替代方案時用（價值工程）。
功能分解Functional Decomposition
按功能拆解系統：頂層功能→子功能→介面。想強化模組邊界與責任劃分時用。
北極星指標North Star Metric
找出核心價值主張、其代理指標、以及防造假驗證——代理指標必須真的不同於核心價值本身。想讓產品策略聚焦單一長期價值指標時用。
問題樹Problem Tree
原因在下、核心問題在中、效果在上，把問題結構化排開，避免把症狀當成原因。跳去想解法之前，先確認問題本身抓對了。
問題陳述Problem Statement
描述現況→預期→落差→影響→限制，建立跨人共同的問題定義。團隊需要先對齊「問題到底是什麼」再吵解法時用。
工作分解結構 WBSWork Breakdown Structure
把交付項目拆成工作包，每包指定負責人與估算。規劃專案、降低遺漏時用。
成功標準Success Criteria
在高風險決策之前，先定義必須／應該／護欄／停止標準，防止事後改標準。任何你可能事後改口「成功」定義的決策之前用。
我們可以如何… HMWHow Might We
把痛點轉成開放、不預設方案的問題（「我們可以如何…」），擴大解法空間。進入創意發想階段之前用，避免不小心先預設了答案。
未來羅盤Future Compass
釐清未來目標與方向感。非診斷工具。
框架轉換Reframing
換角度詮釋痛苦經驗，重新定義「失敗／羞恥／後悔」。非診斷工具。
框架風暴Frame Storming
先產生多個不同的問題框架，再明確選出一個——確保是真的選過，而不是只想到一種角度。要決定用哪個角度看問題之前用。
目標樹Objective Tree
把 Problem Tree 的負面狀態逐項轉成正向目標。做完問題樹後，想直接連到方案設計時用。
目標陳述Goal Statement
把模糊願望轉成明確目標：目標→受益者→時間→成功條件→限制。任務起始時用，降低之後的範圍漂移。
議題樹Issue Tree
把大問題拆成可分析的分支，深度不設限，檢查有沒有遺漏。要為一個龐大、還沒結構化的問題建立分析計畫時用。
邊界批判Boundary Critique
檢視誰是決策者、誰受影響、誰被排除、有哪些資源、隱含什麼價值觀，揭露隱藏的權力與價值假設。決策會影響到不在場的人時用。
邏輯樹Logic Tree
先定好單一分類規則，再展開樹狀結構，防止維度混亂。發現自己拆到一半分類標準跑掉時用。
階層式任務分析Hierarchical Task Analysis
把人類工作拆解成目標→任務→子任務→計畫的樹狀結構。想找出操作負擔或容易出錯的環節時用。
非目標清單Non-goals
明確說出「這次不做什麼」，附理由與重審條件。大型專案想控制範圍與成本時用。

6-3-5 腦力書寫法6-3-5 Brainwriting
6 人×3 個想法×5 分鐘，輪流傳遞接力延伸，結構化又快速產生大量變體。想要腦力書寫的效果又要控制時間時用。
SCAMPER 檢核表法SCAMPER
用 7 個角度（替代／結合／調整／修改／挪用／消除／反轉）系統性改造已有的產品或流程。能產生想法，但不能證明市場需求或商業可行性。
六頂思考帽Six Thinking Hats
讓案主切換多元觀點：情緒、邏輯、批判、創意等，強化整合力。非診斷工具。
創意限制Creative Constraints
以限制媒材方式（只能用紅色、只能用左手）促發非慣性表達與創作彈性。非診斷工具。
創新理論工具 TRIZTheory of Inventive Problem Solving
系統化解決矛盾問題的方法論。面對看似矛盾的內在衝突，用「矛盾解決思維」打開出路。非診斷工具。
反向腦力激盪法Reverse Brainstorming
不直接想「怎麼解決 X」，而是先想「怎麼樣會讓 X 更糟」，再把每個答案反過來變成真正的解法。想解決問題卻一直卡在同樣幾個想法時用。
型態分析法Morphological Analysis
列出問題的多個維度與各維度選項，系統性組合出所有「合法組合」再評估。想窮舉龐大解空間、不漏掉組合時用。
屬性列舉法Attribute Listing
把一個產品／方案拆成屬性，逐項嘗試變換再重組出新版本。想改良一個現有東西時用。
強制關聯法Forced Connections
強制連結兩個不相關概念（列特徵→交叉組合），激發新產品／商業模式創意。卡住、需要真正跳脫的角度時用。
心智圖Mind Map
從中心主題向外長出主枝、次枝、關鍵詞，自由聯想。想快速發散、整理思緒時用。
星爆法Starbursting
用 Who/What/When/Where/Why/How 六個角度發散提問，找出未知與研究問題。需求前期、想找出還不知道的事情時用。
概念圖Concept Map
畫出概念之間「有標籤的關係」（不像 Mind Map 只是無標籤分支），例如「A 導致 B」。想精確表達概念之間邏輯關係時用。
水平思考Lateral Thinking
跳脫邏輯慣性，以非線性方式解題。非診斷工具。
瘋狂 8 法Crazy 8s
8 分鐘畫出 8 個不同概念，強迫自己跳過第一個答案。適合介面／產品概念發想，不適合當最終方案評選。
經典腦力激盪Classic Brainstorming
快速產生大量想法，明確把評判延後到之後獨立的評估步驟。想要大量原始想法、不要邊想邊否決時用。
腦力書寫法Brainwriting
先各自寫下想法，再分享合併，降低定錨效應與從眾心理。跨階級／怕外向者主導討論的團隊用。
蓮花座法Lotus Blossom
中心主題展開 8 個分支，每個分支再各自長出 8 個想法，大量但有結構。想要大量想法但還能事後分群整理時用。
親和圖／KJ 法Affinity Diagram / KJ Method
把大量零散想法一張一張卡片寫下來，靜默分群後命名，找出隱藏主題、降低資訊量。腦力激盪完一堆想法但很亂時用。
設計思考Design Thinking
透過同理、定義、發想、原型、測試解決問題。非診斷工具。
隨機刺激法Random Stimulus
用隨機詞或圖強制找出跟問題的關聯，打破慣性思考。之後需要可行性篩選——它是用來打破思路卡住，不是拿來做最終決定。
類比創意法Synectics
用直接／個人／象徵類比重構問題，追求更深層的創意突破。對引導技巧要求較高，適合工作坊形式進行。
類比映射Analogy Mapping
把其他領域的成功機制對應到你的問題上。想跨行業借鏡解法時用。

3C 分析3C Analysis
從顧客、競爭者、公司三個角度檢視同一個問題，最後明確寫出三者間的契合度結論。想快速、聚焦地判斷公司的產品／服務是否真的契合顧客需求跟競爭位置時用。
Ansoff 矩陣Ansoff Matrix
把一個成長方案歸類到四個象限之一——市場滲透、市場開發、產品開發、多角化——並標示其相對風險。想為提案的成長策略分類、並立刻看出該象限通常帶有多少風險時用。
BCG 成長占有率矩陣BCG Growth-Share Matrix
依成長率×相對市佔率，把投資組合中的每個項目畫在圖上，自動算出落在哪個象限——明星、金牛、問題、狗。想決定投資組合裡的產品或事業單位該加碼、維持還是撤資時用。
PESTEL 分析PESTEL Analysis
掃描六個總體環境面向——政治、經濟、社會、科技、環境、法律——找出事實、趨勢與意涵。想建立外部環境全貌，餵給情境規劃或 SWOT 的機會／威脅那一側時用。
RACI 責任矩陣RACI Matrix
為清單上的每一項任務，指定誰是負責執行（R）、當責（A）、需諮詢（C）、需被告知（I）。專案卡在「這件事到底誰負責」時用。
STEEPV 分析STEEPV Analysis
在 PESTEL 六面向之外再加上第六個維度：價值觀——形塑市場的社會／倫理價值觀。決策對公眾或組織價值觀的變化敏感，不只是受經濟與法規趨勢影響時，用這個取代單純的 PESTEL。
STP 市場區隔定位Segmentation, Targeting, Positioning
把市場區隔、目標選擇、定位跑成真正循序的流程，目標選擇的決策必須指向區隔階段實際產出的某個區隔。想從「整個市場有誰」一路走到「我們要佔據什麼定位」、且不跳過任何一步時用。
SWOT 分析SWOT Analysis
經典的 2x2 分析：內部優勢／劣勢對照外部機會／威脅。想對一個策略情境做標準的第一輪框架分析，之後再接 TOWS 或五力分析做更深入的工具時用。
TOWS 矩陣TOWS Matrix
把既有 SWOT 分析的因子交叉配對成四種策略類型——SO/ST/WO/WT——把靜態的 SWOT 清單變成可執行的策略選項。要接在 SWOT 之後用，不能單獨使用，因為每個配對都會對照你實際的 SWOT 紀錄做驗證。
VRIO 資源分析VRIO Resource Analysis
用四個問題檢驗一項資源或能力：有價值嗎、稀有嗎、難以模仿嗎、組織有效運用嗎，並依此算出對應的競爭意涵，而不是讓你自己宣稱。想檢查一個自稱的「競爭優勢」是不是真的通過全部四關，還是只是剛好擁有的能力時用。
五力分析Porter's Five Forces
從五個經典 Porter 構面評估一個產業的競爭強度：同業競爭、供應商議價力、買方議價力、替代品威脅、新進入者威脅。想了解產業層級的獲利壓力時用；但數位平台與網路效應可能需要額外的平台策略視角補充。
交叉影響分析Cross-impact Analysis
分析一整組事件兩兩之間如何互相改變機率，避免把趨勢誤當獨立事件。多個預測事件彼此可能互相影響時用。
價值主張圖Value Proposition Canvas
把顧客輪廓（任務／痛點／獲益）對照價值地圖（產品、痛點解方、獲益創造者），並記錄產生的契合假設。作為商業模式圖的放大鏡版本，專門檢查價值主張是否真的契合顧客需求時用。
價值鏈分析Value Chain Analysis
把一個事業拆成主要活動與支援活動，找出每項活動的成本驅動因子與價值驅動因子。想找出該在哪個環節降低成本或增加差異化，再進一步跟競爭者做標竿比較時用。
利害關係人圖Stakeholder Map
列出對一個決策有影響力或利益關係的所有各方，每個都標註關係類型（直接／間接／受益者／風險承擔者）。做任何更深入的利害關係人分析（權力利益、顯著性、聯盟圖）前的基礎第一步——沒先列出來，就沒辦法評分。
利益導向談判Interest-Based Negotiation
把每一方表面的立場跟底層真正的利益分開，再找出能滿足真正利益的方案，而不是在立場上各退一步。談判卡住、雙方都在捍衛立場而不是講出真正需求時用（Fisher 與 Ury 經典談判法）。
可能同意區間（ZOPA）Zone of Possible Agreement
比較賣方能接受的最低條件跟買方能接受的最高條件，算出兩者之間是否真的存在可能同意的區間。談判開始前先用，才會知道這筆交易在數學上到底成不成立。
商業模式圖Business Model Canvas
把九個標準商業模式區塊（關鍵夥伴、關鍵活動、關鍵資源、價值主張、顧客關係、通路、客群、成本結構、收益流）畫在同一張畫布上，並明確標記為假設，直到對照真實商業運作驗證過為止。想在投入完整商業計畫前，先用一頁描述整個商業模式時用。
回溯規劃Backcasting
從理想的未來狀態往回推導出里程碑，一路推到今天該做的事。做長期路線圖、從現在往前推導不出方向時用。
地平線掃描Horizon Scanning
系統性掃描各領域／來源找出新興變化訊號，每個訊號都要有來源、日期、地區、狀態、影響、信心度。想提早發現外部變化、不要被打措手不及時用。
外卡情境Wild Cards
加入一個劇烈的非主流事件，重新跑一次策略，測試是否遇到典範轉移。想用真正顛覆性的意外測試策略韌性時用。
市場分析Market Analysis
把市場規模拆解成 TAM（總體市場）≥ SAM（可服務市場）≥ SOM（可獲得市場）的漏斗，並為每個區隔記錄成長率與支持證據。做商業計畫、想界定實際可觸及的市場規模而不只是產業總量時用。
微弱訊號偵測Weak Signal Detection
找出還沒成為主流的訊號，且必須有兩個以上獨立來源佐證才算數（不只是單一軼事）。想提前偵測趨勢又不想追著每個道聽塗說跑時用。
德爾菲法Delphi Method
匿名多輪專家估計（第一輪→彙整→第二輪→分歧程度），保留少數意見而不是強迫假共識。想在不確定的問題上取得專家判斷、又不想被權威效應或從眾左右時用。
情境規劃Scenario Planning
用兩個關鍵不確定因素，建出正好四個完整情境，而不是只押注單一預測。想為多種可能未來做規劃、不依賴單一預測時用。
最佳替代方案（BATNA）Best Alternative To a Negotiated Agreement
找出如果這次談判破局，你手上最好的替代方案，並用它作為評估任何提案的真實底線。談判前先用，才不會臨場憑感覺猜底線。
未來輪Futures Wheel
把一個中心事件展開成直接、間接、結構性（一階／二階／三階）影響。想強迫自己想到明顯的一階影響之外時用。
權力-利益矩陣Power-Interest Matrix
把每個利害關係人依權力×利益畫在四象限圖上（由各自的分數計算得出），分成密切管理／保持滿意／保持知情／持續監控四類。想決定該花多少心力經營哪個利害關係人時用。
歷史類比Historical Analogy
把現況跟歷史先例比較，抽出機制，並明確標出類比不成立的地方。想借鏡歷史又避免流於表面類比時用。
異常個案分析Outlier Analysis
先排除資料錯誤，才深挖異常個案背後的機制，不能跳過驗證就直接編故事。奇怪的資料點可能是真實新現象時用。
精實畫布Lean Canvas
Ash Maurya 把 Business Model Canvas 改成新創專用版：拿掉「怎麼經營一家已存在的公司」的 4 個區塊（關鍵夥伴、關鍵活動、關鍵資源、顧客關係），換成「怎麼開始一家新公司」的 4 個區塊（問題、解決方案、關鍵指標、難以模仿的優勢）。剛起步、還沒驗證過的新創點子，BMC 那套營運導向的區塊還用不上時用這個。
聯盟關係圖Coalition Mapping
畫出每個利害關係人的利益、權力、資源，並推估在特定議題上誰可能結盟。在有爭議的決策中，結盟關係跟個別立場一樣重要時用。
藍海策略Blue Ocean Strategy
在策略畫布上畫出跟競爭者對照的價值曲線，再把每個競爭因素套進消除／降低／提升／創造（Kim 與 Mauborgne 的 ERRC 表）四個動作。想設計一個真正無人競爭的全新市場空間，而不是在既有市場正面競爭時用。
誘因圖Incentive Mapping
為每個利害關係人做一張卡片，涵蓋他的目標、誘因、限制、風險。想預測一個人實際上會怎麼做，而不是你以為他應該怎麼做時用。
賽局理論Game Theory
把一個策略互動建模成參與者、策略、報酬，並在報酬都揭露後算出均衡解。結果不只取決於自己的選擇、還取決於對方怎麼做時用，想嚴謹推理而不是憑直覺。
跨國比較Cross-country Comparison
在明確宣告的標準化基準下比較多個國家／地區的指標。想找出地區差異又不想拿蘋果比橘子時用。
跨產業移植Cross-industry Transfer
把其他產業針對相同工作／限制的解法機制移植過來。想避免重新發明已經存在的解法時用。
鄰近學科搜尋Adjacent Discipline Search
從真正的鄰近學科（不是團隊現有專業）找遺漏變數，並引入其模型。想降低單一專業盲點時用。
顯著性模型Salience Model
針對每個利害關係人評估三個是非題——權力、正當性、急迫性——每一項都要求寫理由，再依符合幾項算出顯著性等級。想在做更完整的利害關係人圖之前先快速分流、決定先關注誰時用。
黑天鵝演練Black Swan Exercise
串起尾端風險事件→曝險程度→存活能力→避險措施，強化面對低機率高衝擊事件的韌性。想提早準備承受不起的意外時用。
做不做得起來、划不划算？11 個
TELOS 可行性檢核TELOS Feasibility
檢查技術、經濟、法律、營運、時程五個必要面向，每個都要有實際證據，不能只證明「技術做得到」就說可行。想從不只工程角度檢查專案可行性時用。
內部報酬率 IRRInternal Rate of Return
算出讓現金流淨現值剛好等於零的折現率，一個直觀的報酬率數字。想拿投資報酬率跟門檻報酬率比較時用。
單位經濟效益Unit Economics
檢查每個客戶／交易到底賺不賺錢（客單價／毛利／取得成本／終身價值／回收期／流失率），邊際貢獻是負的就標記不可擴張。想在規模化之前抓出「營收成長但越賣越虧」時用。
實質選擇權Real Options
把延後／擴張／退出當成選擇權（觸發條件、成本、未來情境價值），而不是一次性 yes/no。想分階段決策、不想一次全押時用。
成本效果分析Cost-Effectiveness
用「每單位同樣成果的成本」比較方案，適合效益很難換算成金額的情況。效益沒辦法貨幣化、但可以量測時，用它取代成本效益分析。
成本效益分析Cost-Benefit Analysis
把方案的成本與效益貨幣化後全生命週期比較，一定要做折現與敏感度分析，無法定價的項目要明確標示，不能硬掰一個數字。用金額比較選項、又想誠實面對算不出價格的東西時用。
損益兩平分析Break-even Analysis
算出固定成本剛好被邊際貢獻打平所需的銷售量。想知道一個方案最少要賣多少才不虧錢時用。
淨現值分析 NPVNet Present Value
把未來一系列現金流用折現率換算回今天的價值。想公平比較不同時間點回收的投資時用。
總持有成本 TCOTotal Cost of Ownership
加總全生命週期 12 個必要成本類別（取得、導入、營運、人力、退場、遷移等），看出隱性成本與被綁死的風險。選供應商／平台前，牌價背後藏著真實成本時用。
蒙地卡羅模擬Monte Carlo Simulation
用大量隨機抽樣模擬一個不確定結果的分布，得到機率而不是單一數字。有很多不確定因素、想知道最好／最壞／最可能情境的機率時用。
財務假設Financial Assumptions
記錄支撐一份商業計畫數字的財務假設（幣別、折現率、期間、現金流預測）。做任何財務預測之前的第一步。

事前驗屍Pre-mortem
假設專案已經失敗，每人先獨立列出可能原因，再分群、排序、訂出預防／偵測／復原措施。專案開始前想提早揪出真正隱憂時用。
信心校準Confidence Calibration
檢查你說的信心程度是不是真的準（預測 vs 實際結果→校準曲線），抓出過度自信。想知道自己說的「9 成把握」歷史上到底準不準時用。
假設地圖Assumption Mapping
依「錯了會怎樣×不確定程度」把假設排進四象限，知道該先驗證哪個。想決定先測試哪個高風險假設時用。
假設登記表Assumption Registry
正式記錄每個假設的內容、類型、證據、信心度、狀態，讓假設不再藏在文字裡。想維護一份持續可見的「這個計畫在賭什麼」清單時用。
危害與可操作性分析 HAZOPHazard and Operability Study
用一組標準引導詞（沒有／更多／更少／反向等）系統性找出流程可能的偏差。做高風險流程的完整性風險分析時用。
反例搜尋Counterexample Search
針對一個規則／主張找邊界案例，篩出真正推翻它的反例。想測試一個規則的適用邊界時用。
反證搜尋Disconfirming Evidence
主動去找「不支持自己想法」的資料，而不是只找支持的證據，降低確認偏誤。驗證一個自己深信的判斷前用。
圖爾敏論證模型Toulmin Model
逐欄填寫主張／依據／立論理由／後盾／限定詞／反駁，防止論證缺少從證據到結論的推理橋梁。想檢查一個論證是不是真的站得住腳、還是只是空口斷言時用。
壓力測試（情境）Stress Testing
設計極端但合理的情境，測試方案在壓力下的崩潰點在哪。想知道一個方案的韌性極限時用。
失效模式與影響分析 FMEAFailure Mode and Effects Analysis
逐步檢查功能→失效模式→影響→原因→現有控制→嚴重度→機率→可偵測度→行動優先序，找出最該優先處理的風險點。上線前做風險盤點時用。
推論階梯Ladder of Inference
依序爬過資料→意義→假設→結論四個階梯，找出認知跳躍發生在哪一步。有人跳到結論、想看清楚推理到底哪裡斷掉時用。
獨立裁決Independent Judge
在 Red Team 攻擊、Blue Team 防守都做完後，由第三方角度做最終裁決。想要不偏袒任一方的最終結論時用。

對系統依賴的套件、建置流程、第三方供應商做威脅建模，而不只是看自己的程式碼。新增依賴套件、CI/CD 步驟或供應商整合時用，因為就算自己的程式碼乾淨，這些也可能變成入侵管道。
保留與刪除模型Retention / Deletion Model
定義每種資料要保留多久、怎麼刪除（硬刪除／軟刪除／匿名化）。想規劃合規的資料保留政策時，提早想清楚用。
備份還原演練Backup / Restore Drill
記錄一次真實的備份還原演練，證明備份真的能用，而不是等到出事才發現壞了。定期對重要資料做這件事。
品質屬性情境Quality Attribute Scenario
把模糊的非功能需求（穩定、安全、快）轉成可測試的具體情境（來源→刺激→產物→環境→回應→量測）。寫需求或驗收標準太空泛時用。
壓力測試（工程）Stress Test
把負載推到超過正常水位，找出真正的崩潰點以及事後能不能恢復。想知道系統真正的上限，不只是舒適運作範圍時用。
安全控制對照表Security Control Mapping
把每個識別出的威脅對應到實際緩解它的控制措施，找出沒有控制措施的威脅、以及不知道在防什麼的控制措施。做完任何威脅建模後的收尾步驟，用來證明涵蓋率，而不是憑感覺假設有涵蓋。
容量模型Capacity Model
用工作量成長對照資源係數，算出還有多少餘裕，同時防容量事故與過度採購。要擴充資源前，或要說明現在還不需要擴充時用。
實體關係圖 ERDEntity-Relationship Diagram
把實體、屬性、關係建模成結構化的圖表資料紀錄。設計或整理資料庫結構時用。
復原時間目標／復原點目標 RTO / RPORecovery Time Objective / Recovery Point Objective
定義一個系統最多能停機多久（RTO）、最多能損失多少資料（RPO）。想提早訂出具體的災難復原目標時用。
擴張-收縮式遷移Expand-Contract Migration
把資料庫改動拆成「先擴張（新舊並存）再收縮（確定都遷移完才刪舊的）」兩階段，做零停機的破壞性 schema 變更。正式環境要改資料庫結構時用。
攻擊樹Attack Tree
把一個攻擊目標拆解成 AND/OR 子目標，一路拆到最基本的攻擊技巧，每個節點標註攻擊者的成本／技能／可偵測性。想畫出攻擊者達成某個目標的所有路徑、比較哪條路徑對他們最便宜時用。
服務等級指標／目標／協議 SLI / SLO / SLAService Level Indicator / Objective / Agreement
定義服務可靠性要量測什麼（SLI）、目標值（SLO）、對外承諾（SLA）。這是用 Error Budget 或 Canary Deployment 之前的基礎工作。
架構取捨分析法 ATAMArchitecture Tradeoff Analysis Method
針對一個架構方案，系統性找出敏感點、取捨點、風險、非風險四類發現。要驗證架構設計禁不禁得起壓力測試時用。
架構取捨矩陣Architecture Trade-off Matrix
用權重跟評分比較多個候選架構方案，含敏感度分析。要在多個架構選項之間做決定時用。
架構決策紀錄 ADRArchitecture Decision Record
記錄一個架構決策：脈絡、考慮過的選項、最後決定、後續影響，讓未來的人知道當初為什麼這樣選。做重大技術選型時用。
架構適應度函數Architecture Fitness Functions
把架構的不變量寫成可自動化檢查的測試／指標，持續守住不讓架構隨時間腐化。想長期守住某個架構原則時用。
機密資訊威脅檢視Secrets Threat Review
檢視應用程式的機密資訊（API 金鑰、token、憑證）如何儲存、輪替、存取，找出硬編碼、寫進 log、權限過寬等外洩路徑。新增任何機密資訊或憑證儲存機制前用。
正規化Normalization
用正規化規則檢查 schema，移除重複資料與更新異常。設計或審查關聯式資料庫結構時用。
浸泡測試Soak Test
用穩定負載跑很長一段時間，抓短時間負載測試抓不到的緩慢退化（記憶體洩漏、資源耗盡）。長時間運行的正式環境上線前用。
混沌工程Chaos Engineering
建立穩態假設、限定影響範圍、注入特定故障、驗證系統是否自動恢復，不如預期立即停止。想在真的出事前主動找出韌性缺口時用。
演習日Game Day
用預先設計的情境、指派角色、注入問題、事後檢討。想在真正出事前先演練事故應變流程時用。
濫用案例Abuse Case
寫使用者故事的負面鏡像版：一個惡意使用者會如何刻意濫用這個特定功能，而不是泛泛談攻擊者怎麼攻破系統。跟正常使用案例／使用者故事一起寫，讓濫用情境在設計階段就被考慮，而不是上線後才發現。
發布就緒審查Release Readiness Review
上線前一次檢查變更、資料、安全、可觀測性、回滾、容量，抓出單一團隊會漏掉的跨領域風險。上線前的最終 go/no-go 檢查用。
相依關係地圖Dependency Mapping
畫出服務／廠商／資料之間的相依關係，找出隱藏的單點故障。想知道「這個東西掛了會拖累誰」時用。
絞殺者模式Strangler Fig Pattern
找一個切入點，逐步用新系統取代舊系統的一小塊，驗證後擴大範圍，最後淘汰舊系統。要漸進式汰換遺留系統、不敢一次重寫時用。
藍綠部署Blue-Green Deployment
新版本（Green）完整部署驗證後才切流量，舊版本（Blue）保留做即時備援。需要近乎瞬間回滾能力的上線時用。
負載測試Load Test
記錄逐步加壓下的真實負載測試數據（吞吐量、延遲、錯誤率）。上線或預期流量暴增前，想知道系統真實承載能力時用。
資料保護／隱私影響評估 DPIA / PIAData Protection / Privacy Impact Assessment
針對一項資料處理活動，正式評估其目的、必要性／比例原則、受影響當事人、風險與控制措施。要推出任何處理個資的功能或流程前用，尤其是法規要求要有書面評估的情境（如 GDPR 第 35 條）。
資料品質維度Data Quality Dimensions
用一組標準品質維度（完整性、準確性、一致性、時效性等）評分一份資料集。想有系統地檢查資料能不能信任時用。
資料契約Data Contract
定義資料生產方與消費方之間約定好的資料格式與語意，避免欄位改動悄悄弄壞對方系統。一個團隊的資料要餵給另一個系統用時用。
資料對帳Reconciliation
比對兩個資料狀態的筆數／checksum／業務不變量，找出差異並解決，證明遷移真的完整。資料遷移或同步完成後用。
資料血緣Data Lineage
追蹤一個資料欄位從來源、蒐集、轉換、資料集，一路到最後被拿去做決策的完整路徑。想回答「這個數字到底哪裡來的」時用。
金絲雀部署Canary Deployment
分階段放量（1%→5%→25%→50%→100%），任何階段不健康就立刻回滾。要限制風險爆炸半徑的上線時用。
錯誤預算Error Budget
從 1-SLO 算出燃燒速率，用它決定發布節奏（預算快用完就放慢腳步）。想讓「該衝功能還是顧穩定」變成有數據依據的決定時用。
零信任架構檢視Zero Trust Review
依零信任原則檢視系統的存取架構：每次請求都明確驗證、最小權限、假設網路已經被入侵。想稽核設計是否還隱性依賴「內部網路等於可信任」這個假設時用。
領域驅動設計 DDDDomain-Driven Design
把複雜業務領域拆成子領域、限界脈絡、脈絡地圖。系統邊界模糊、想釐清「這塊該歸誰管」時用。

合規缺口分析Compliance Gap Analysis
機械式算出「要求的控制」跟「已實作的控制」之間的差距，附嚴重度與補救計畫。想快速知道能不能在受規管領域上線時用。
在地化審查Localization Review
檢查 13 個必要面向（語言、日期時間、貨幣、單位、地址、稅務、無障礙等）——翻譯不等於在地化。要在新地區上線前用。
市場准入控管Market Admission Control
進入新市場的 go/no-go 關卡，涵蓋 7 個階段（法規時效、資料落地、AI 供應商、安全、在地化、產業別控管、真人簽核）——任何關鍵未知一律阻擋。進入任何新地理市場前用。
文化脈絡審查Cultural Context Review
用在地證據評估 8 個文化因素（信任、權威、隱私觀感等）——是待驗證的假設，不是刻板印象。高風險決策要有在地資料／訪談／問卷／專家審查，不能只靠猜。
法律衝突審查Conflict-of-Law Review
多個法律衝突時決定適用哪一個，且任何衝突的最終判定都要有真人法務簽核（絕不自動判定）。跨境活動可能受多套法律管轄時用。
法規前瞻掃描Regulatory Horizon Scan
只從官方來源（政府／主管機關／立法紀錄）追蹤即將上路的法規。想避免被新法規突襲時用。
管轄權解析器Jurisdiction Resolver
從 11 個以上維度（實體、使用者位置、資料位置、供應商、產業別等）解析真正適用的管轄權，不只是「使用者在哪個國家」這麼粗略。單純猜國名不夠精確時用。
義務對應控制措施Obligation-to-Control Mapping
把法律義務轉成可追溯的工程控制措施，附負責人、證據、測試。想確保法務跟工程真的對得上焦時用。
資料落地評估Data Residency Assessment
決定每一類資料在法律上能存放／處理在哪裡，涵蓋資料主體、法規、合約。想支援資料主權要求與跨境資料流動決策時用。
適用法規圖譜Applicable Law Graph
建立法規來源與適用條件的圖譜（管轄區→來源→生效日→範圍→衝突）。想支援跨管轄區的版本與衝突法推理時用。
