# HCI-30 — Wave 1 local skeleton

Canonical product root: `D:\Work\Projects\internal\hci30\`. HCI runtime code belongs here; architecture, ADR, and research records remain under `D:\Work\agency-os\docs\HCI\`.

Start with `docs\HCI30_DELIVERY_PLAN.md` for architecture and gates, then `docs\HCI30_EXECUTION_PLAN.md` for the ordered implementation backlog.

This is an **isolated, synthetic-only PostgreSQL 15.8 test skeleton**. It has no host-port mapping, production configuration, portal integration, real-person fixture, or deployment path.

Run `powershell -ExecutionPolicy Bypass -File .\scripts\test-wave1-local.ps1` after Docker Desktop is running. The runner rejects non-local Docker contexts, creates a per-run compose project and generated temporary password file, runs migrations and negative tests, then tears down only that project and removes the password file. It must never be pointed at an existing database.

A green suite is not evidence that a gate is closed. `powershell -ExecutionPolicy Bypass -File .\scripts\mutation-check-wave1.ps1` deletes each control in turn and requires the suite to go red on the specific assertions covering it. If any mutation survives, those assertions are not constraining the schema and the green result must not be trusted until they are fixed. Run it whenever a trigger, grant, constraint, or policy changes. It exists because the first version of this suite could not fail at all.

The Node-level gates and specs under `packages/contracts/` and `packages/intelligence/` (ADR-0004 gates 4-5, the P0-04 Trust-Domain roll-up formula including its domain-internal `dimension_disagreement` signal, the shared dimension-score and evidence-refs validators, the confidence-spec method-to-dimension combination, the risk-spec severity-floor detection, the evidence-quality-spec single/multiple-source classification, and the standalone `04_HCI30_PRODUCT_SPEC.md:138` decision bias-check blocking gate — not a P0-04 spec, see `docs/intelligence/HCI_DECISION_BIAS_CHECK_GATE.md`) have their own equivalent, `powershell -ExecutionPolicy Bypass -File .\scripts\mutation-check-node-gates.ps1` — coarser than the SQL harness (it checks whether the target test file's suite goes red at all, not whether specific named assertions flip; see the script's own header for why) but real non-vacuity proof by the same standard, plus a baseline no-op gate proving the sandbox itself is complete before any mutation runs. Run it whenever one of those files changes.

Three of P0-04's seven named specs (`HCI_PERMISSION_SPEC.md`, `HCI_CONTRADICTION_SPEC.md`, `HCI_TIME_DECAY_SPEC.md`) exist as files but deliberately contain no rule — each records precisely why it remains blocked (an undefined entity shape, a missing data-model layer, or an undecided parameter) rather than inventing one speculatively. See each file's own Status section.

Implemented gates are limited to the approved HD-03/04/05 slice: Person-only subject constraints, separate permission records, DataSubjectRequest event history, identity-confirmation admission, and mandatory tenant RLS. HD-06 through HD-23, plus the 8 constitutional ADRs and the tenancy-principal gap, were all decided 2026-09-02 as ADRs (`agency-os/docs/HCI/HCI_AI_LEGO_Blueprint_v2/governance/ADR_INDEX.md` is authoritative for current state) — decided is not implemented: their runtime gates (schema, triggers, tests) remain open and none of this migration's tables reflect them yet. Passing synthetic tests is not a claim of legal compliance or production readiness.
