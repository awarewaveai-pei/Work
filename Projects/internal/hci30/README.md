This is an **isolated, synthetic-only PostgreSQL 15.8 test skeleton**. It has no host-port mapping, production configuration, portal integration, real-person fixture, or deployment path.

Run `powershell -ExecutionPolicy Bypass -File .\scripts\test-wave1-local.ps1` after Docker Desktop is running. The runner rejects non-local Docker contexts, creates a per-run compose project and generated temporary password file, runs migrations and negative tests, then tears down only that project and removes the password file. It must never be pointed at an existing database.

A green suite is not evidence that a gate is closed. `powershell -ExecutionPolicy Bypass -File .\scripts\mutation-check-wave1.ps1` deletes each control in turn and requires the suite to go red on the specific assertions covering it. If any mutation survives, those assertions are not constraining the schema and the green result must not be trusted until they are fixed. Run it whenever a trigger, grant, constraint, or policy changes. It exists because the first version of this suite could not fail at all. It isolates each mutation with a `BEGIN`...`ROLLBACK` transaction against a schema built once, not a full 11-migration rebuild per mutation, so a full run of the whole mutation set takes well under two minutes.

P0-09's RLS enforcement gate (`21_HCI_TOP_TIER_GAP_ANALYSIS.md`) is partially closed: `RLS-COMPLETENESS-01`/`02` in `wave1-negative-tests.sql` query the live catalog for every table with a `tenant_id` column and assert RLS is enabled, forced, and policied, so a future migration that adds a tenant-scoped table and forgets RLS entirely is caught without a new per-table test. This is structural, not functional — it does not replace a table's own `RLS-LEAK-NN` real-query test, which is still required to prove a policy's logic is actually correct, not merely present.
