## 4. 功能逐項解釋與驗收

下列「功能」源自使用者要求；操作細節是為了讓工程師能實作及驗收的建議最低規格，不是使用者另外逐項指定的軟體／格式／效能承諾。

### 4.1 把素材剪成完整影片

不是只能單段裁切或加一層文字。必須能管理多個來源，排列順序，調整片段長度，加入旁白／音樂／字幕，最後得到一支可播放、有聲音、比例正確的影片。

範例流程：匯入兩段 MOV／MP4 → 剪掉頭尾 → 加一張圖片與片頭 → 疊字幕 → 混入旁白與背景音樂 → 保存 → 關閉重開 → 輸出完整影片。

### 4.2 多軌、裁切與時間軸

| 功能 | 使用者能做什麼 | 最低驗收 |
|---|---|---|
| 多軌剪輯 | 主影片、疊加影片、圖片、文字與多路音訊在不同軌道同時存在；顯示／靜音分開控制 | 重疊片段的層次與聲音正確；保存重開後軌道、位置與長度不變。軌道數與新增／刪除方式需明示，不能仍只靠固定五軌就宣稱專業多軌完成 |
| 精細裁切 | 以影格定位、設定入點／出點、分割、拖動片段邊界；不修改來源檔 | 在已知畫面編號的測試片精確剪到指定影格，重開及輸出不偏移 |
| 時間軸編排 | 移動、複製、刪除、關閉空隙／連動前移、吸附、縮放、逐格前後、撤銷與重做 | 修剪後相鄰片段不被意外覆蓋；音畫連動規則明確，撤銷可回復 |
| 轉場 | 在片段交界加淡化、溶解或其他可用轉場，調整長度與方向 | 兩段確實混合而非直接切換；可預覽，輸出時序一致；素材不足時有明確處理 |
| 調色 | 曝光、對比、白平衡／色溫、飽和度等基本調整，可重設與比較前後 | 色彩參數會影響真實輸出，重開保留；明示色彩空間／範圍，不能以換縮圖當調色 |

時間以影格／有理時間儲存，明確區分來源幀率與專案幀率，不能靠持續累加浮點秒數導致字幕、裁切及聲音越來越偏。

### 4.3 字幕、動態字幕與片頭

| 功能 | 解釋 | 最低驗收 |
|---|---|---|
| 一般字幕 | 有時間範圍與文字的字幕項，可編輯內容、起訖、樣式與位置；至少驗證 SRT 匯入／匯出及燒錄 | 繁中、多行、標點、時間重疊可正確處理，保存後仍可改文字與時間。字幕檔與燒錄影片分別可用 |
| 動態字幕 | 字詞或整句隨時間進場、放大、變色、逐字出現等；保留可編輯文字與動畫 | 可改文字、樣式與關鍵影格；同一時間的預覽與輸出一致。逐字高亮若需要字詞級時間，來源與缺失時行為必須明確 |
| 片頭動畫 | 可修改標題、圖片／Logo、背景與進出場動畫，作為可重用合成片段 | 修改片頭文字後重渲染回原剪輯，長度、位置與透明度正確；不能只提供一段固定 MP4 |

一般字幕不是「一堆只能看、不能再改的圖片」。動態字幕也不等於把整句字幕淡入就宣稱所有動態字幕需求已完成，需列實際可用動畫。自動語音辨識是可沿用／另接的輔助流程；此次不能默認所有字幕工作都要付費 AI。

### 4.4 音訊混合

同時處理原片聲音、旁白、背景音樂與音效；可分別調整音量、靜音、淡入淡出與起始時間。軌道與片段的音量語義要一致，音量數值須有限且有合理界限，保留 0 靜音。

驗收使用含已知音調／節奏的短片與兩路音訊：預覽可聽到，輸出確實含音軌；剪接點沒有意外斷音，時長與影像同步，超峰值有可見量表或處理說明。瀏覽器音訊啟動可能需要使用者操作，不能以預設靜音播放器掩蓋錯誤。

### 4.5 2D 動畫、視覺特效與合成

| 功能 | 解釋 | 最低驗收 |
|---|---|---|
| 圖層 | 影片、圖片、文字、形狀等可疊放，管理順序、可見性、透明度、混合模式與父子關係 | 遮擋順序、半透明及父子變形正確；保存重開能繼續編輯 |
| 2D 變形 | 位置、縮放、旋轉、錨點／樞紐可調；圖層可跟隨父控制器 | 改樞紐後旋轉符合預期，父控制器帶動子物件；不是只改 CSS 預覽 |
| 遮罩 | 用形狀／路徑控制圖層哪裡顯示，可反相、調整邊緣與羽化 | 遮罩邊界與透明度能預覽並輸出；遮罩本身可保存、再編輯 |
| 遮罩合成 | 以另一圖層的透明度／亮度作可見範圍，例如文字內播放影片 | 驗證圖層內容、遮罩及其各自動畫能同時運作，透明成果回時間軸不變黑底 |
| 關鍵影格 | 在不同時間設定屬性值，系統計算中間變化 | 能新增、移動、刪除、複製、逐格定位；改一個關鍵影格後預覽與輸出同時更新 |
| 動畫曲線 | 調整速度與數值隨時間的變化，如線性、停格、緩入緩出、Bezier 控制 | 有可操作曲線／控制點，能比較線性與緩動結果，重開保留曲線 |
| 表達式 | 用受支援的運算控制屬性，如循環、擺動、連結另一屬性 | 公布支援語法與屬性；有錯誤定位，死循環／超時不拖垮工作台；不能取得主系統金鑰或任意檔案 |
| 視覺特效 | 對圖層加入並調整模糊、發光、色彩等實際效果，可設定順序與旁路 | 選定少量效果完成預覽／輸出一致驗證，列實際可用清單，不拿上游效果數量當本站已完成數量 |

3D 場景、攝影機與燈光在 3D 階段（計畫卡 P5）做。2D 畫面的縮放、平移、旋轉與景深視覺效果，不應被包裝成已實作 3D 系統。

### 4.6 2D 綁定與骨架動畫：分三層驗證

**A. 可操作的圖層／肢體綁定**

把頭、身體、上臂、前臂等分層素材組成角色，指定樞紐、父子階層與控制器。旋轉上臂時，前臂／手掌要跟隨。骨架與原素材分開保存。

**B. 網格與 Puppet 變形**

對單張或局部圖片建立網格，放置控制釘，拉動後畫面跟著變形；可設定旋轉／縮放，記錄控制點動作，對頭髮／衣物做跟隨。

EffectCraft 已有官方 Puppet 與 rigging 說明，包含控制釘連接 null 控制器、控制器的父子階層，可用來建立肢體。**這確實是 2D rigging，不能再說它完全不能綁定。**

**C. 骨骼鏈與進階控制**

建議要驗證骨骼／肢體鏈、骨長、關節限制、正向運動學（FK，轉動上臂帶動前臂）、反向運動學（IK，拖手掌由系統求解手肘）、權重／變形影響範圍，以及控制器與角色姿勢。這些是將「2D 綁骨架」轉成可交付規格的建議細項；上游是否完整支援，尚未驗證。

骨骼階層、IK／FK 與網格權重不能只靠功能名稱認定已具備。如果 EffectCraft 只能完成 A、B，請明列 C 的缺口與補足方法；不能把 Puppet 改名成「完整骨架系統」。

**建議實際工作流程**：匯入已分層角色 → 對齊樞紐 → 建立肢體／控制器關係 → 設定變形範圍 → 在不同時間擺姿勢 → 調整曲線 → 預覽 → 保存角色及動畫 → 輸出透明動畫片段 → 回影片剪輯。

**最低演示案例**：一個具有身體、上臂、前臂與手掌的角色，做抬手與揮手；改控制器後手肘與手掌依規則動作。另驗證一個有 Puppet 網格的柔性部位。保存重開後仍可修改控制器與關鍵影格。

如果納入 IK／權重編輯，另展示拖手掌的求解結果與改權重前後的差異。若本階段未實作，就在能力表中保留「未完成」，不降低總需求或宣稱全部交付。

單張圖片自動拆部件、自動補被遮住的肢體、自動建骨、動作捕捉，都不是「2D 綁定」必然附帶的能力。本次沒有要求先做這些 AI 自動化；初版可由使用者提供分層素材並手動綁定。

### 4.7 保存、互通與輸出

- 動畫／角色／合成需要保留原生可編輯專案，不能只存渲染成果。
- 主時間軸記錄片段的原專案引用與版本；可「開啟來源專案 → 修改 → 更新片段」。更新應可取消／回復，不靜默覆蓋已用版本。
- 跨引擎的第一階段可採透明 PNG 序列與獨立音訊等已驗證中間格式，輸出前對齊幀率、起始影格、時長、色彩與 alpha。這是交換成果，不代表所有原生物件可跨引擎無損編輯。
- 原有輸出比例需保留：16:9、9:16、1:1、4:5、4:3。新引擎設定不能把 4:5、4:3 又弄丟。
- 首個驗收輸出可先鎖定一種經驗證的 MP4／H.264＋AAC 配置，再擴大格式；這不是承諾所有編碼都支援。
- MOV／MP4 是容器；需辨認編碼、旋轉、音軌與幀率。不支援預覽的來源，保留原檔並產生代理，不再出現「副檔名可選，載入卻無聲或黑畫面」又不說明原因。
- 字體缺失、素材遺失、記憶體不足、渲染失敗，要有可理解的原因與復原路徑。
