說明客戶來源、付款方、操作人，以及系統尚缺的項目。

每個系統都要過的規則

這三條寫在 ADR 017 §0b，測試會擋，不靠記憶。

  • 同一個模式整套新系統先在 System Foundry 答「要／不要」，再執行 scripts/new-product.mjs --from-foundry；小工具直接執行 new-product.mjs 答五題。兩條路都產生同一份登記列、自己的門、自己的資料、收費前只問 can() 的骨架。手寫一列，測試紅燈。
  • 離開 WordPress 也能跑付款、登入、CRM 都在接頭後面，接頭的值是設定。整套測試以 payments=local、login=local、crm=none 跑一遍必須全綠。WordPress 是今天的門口與收銀台，不是房子。
  • 樂高：選配與串接功能用 features 與方案決定；買斷能單獨裝哪些積木由 standalone 與 dependsOn 決定；積木之間只走 API 與簽章事件，不讀對方的表。

現況

客戶目前無法自行登入，也尚未收費；現在只有自用與代操。

  • 沒有客戶可自行登入今天才開放：員工替客戶開立帳號，寄出設定密碼信；prod 缺少 RESEND_API_KEY，portal 的公開註冊仍關閉（WORKLOG 2026-10-16 續8、續10）
  • 沒有已有付費客戶0062 合約 0 筆、錢包帳本 0 筆、Woo 尚未販售點數包（ADR 015:13、ADR 017 脈絡）
  • 沒有買斷授權檔、安裝程式與模組清單均未建立（順序 5）
  • 沒有許可判斷lib/entitlements 不存在；認知平台 check_entitlement 永遠回傳 grant（check.py:25）

五種客戶

每種客戶由三個答案決定：裝在哪、錢從哪來、誰操作。答案屬於客戶帳戶與每次請求，不屬於產品，所以每個產品五種都有、不用選。新增客戶類型只需增加一列，不必修改程式。
