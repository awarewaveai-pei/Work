# Card 10 — the group: tables, owner kind, membership, erase (foundation F1)

## Decision
Required reading: `COS/docs/platform/STEP34_SHARED_RULES.md` §1, §2 (all five invariants G1-G5) and `COS/docs/platform/STORAGE_SWITCH.md` (lock map; shared lock for writers, exclusive for erase). A group is the owner of the records a few people write together. This card builds the container only: no block's kinds.

## Constraints
- Migration `COS/ai_lego/data/migrations/versions/0002_groups.py`: the four tables of §2 (raw SQL via `op.execute`, tenant_id on every table, foreign keys within the tenant, CHECK constraints for every `in (...)` list, indexes for `(tenant_id, identity_id)` on members and `(tenant_id, group_id)` on invites), a `downgrade` that drops them. Mirror the style of `0001_baseline.py` (read it). Add a row to its top comment table if it has one.
- `record_log.OWNER_KINDS` gains `"group"`, `Owner.group(group_id)`; `DocKind.owner` may be `"group"` (validate in `doc_kinds.py`, no other behaviour change). Read how `case` and `person` owners are used by `CaseDocs.save/delete/current` and by `erase_*` first; groups follow the same path (`CaseDocs` stays the one writer).
- `require_group(connection, tenant_id, group_id)` beside `require_case` in the repository that holds `require_case` (same shape, same lock scheme as the PostgreSQL port uses for cases: shared advisory lock per (tenant, group) for writers, exclusive for erase). A write to a closed group raises `GROUP_CLOSED` unless the kind has `after_close=True` (add that DocKind flag, default False); to an erased group `GROUP_ERASED`. `case_gone`-style helper in `ai_lego/errors.py` so a route turns both into the same 404 as a missing group.
- Repository methods (repository file that owns accounts/projects; keep SQL visible): create_group (the creator becomes convener, one transaction), get_group_for(identity) (None when not a current member: callers answer 404 identically), list_groups_for, add_member (used by invitations later), leave_group (G3, G5), close_group, erase_group (G4: one region transaction removing group-owned events through `record_log.delete_owned`, members, invites, consents naming the group; then nothing else).
- Routes in new `COS/ai_lego/apps/api/blocks/groups.py` (router discovered like the other blocks): `POST /groups`, `GET /groups`, `GET /groups/{id}`, `POST /groups/{id}/leave`, `POST /groups/{id}/close`, `DELETE /groups/{id}` (convener only). Same session dependency and error mapping as the case routes; non-member = the same 404 body as a missing group (G2).
- Do not add invitations, visibility rules or any block kind here (cards 11-13).
- Plain short Chinese in every message a person can read; add the error words to `COS/apps/cognitive-web/lib/errors.ts` (a union script refuses duplicate keys: run it as `tests`/vitest do).

`tests/unit/test_groups_core.py`: G1 (a write to a closed group refused; an `after_close` kind allowed; a race with a real second connection: a writer holding the shared lock while erase starts -> erase waits for that transaction only, a writer arriving after the erase committed gets `GROUP_ERASED`, nothing lands after); G2 (a non-member and a missing group give identical status and body); G3; G4 (erase removes group records, member rows, invites, consents naming it, leaves each member's case and person records intact); G5 (the last convener cannot leave; leaving after handing over works); migration up/down/up and the CHECK constraints refuse a bad role/status/purpose; tenant isolation (a member of tenant A cannot reach a group of tenant B by id). Also: `python -m unittest tests.unit.test_pg_foundation tests.unit.test_record_log tests.unit.test_step2_foundation` stay green.
