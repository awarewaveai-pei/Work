# Card 40 — TEACH: lessons and practice cases as versioned content (and the loader that guards them)

## Decision
Required reading: `STEP34_SHARED_RULES.md` §11, §13; the card `docs/platform/step34-cards/TEACH.card.txt` (every line is a requirement); `BLOCK_BUILD_GUIDE.md`; the ruleset mechanism `COS/ai_lego/platform/rulesets/__init__.py` (a changed text without a new version fails). Lessons and practice cases are reviewed CONTENT: YAML files, loaded into rulesets, never database rows.

## Constraints
- Folder `COS/ai_lego/platform/lessons/`: `__init__.py` (the loader), `lessons/*.yaml`, `cases/*.yaml`, `HISTORY.json` (`{name: {version: fingerprint}}`, same meaning as the `HISTORY` dicts of the other rulesets). The loader returns `Ruleset("teach.lessons", "TEACH", "課", version, maintainer, items)` and `Ruleset("teach.practice_cases", ...)`; their version is the highest `version` among the files and the fingerprint test is the existing one (extend `tests/unit/test_step2_foundation.py::RulesetTests` style in your own test; do not edit that file). Editing a file's text requires bumping its `version`, adding the new fingerprint to `HISTORY.json`: a test fails otherwise.
- Lesson file: `{id, subject, version, state: draft|reviewed, minutes (1-5), title, text, example, teaches: [..]}`. `subject` is a tool id of the platform (read how tool ids are listed: `ai_lego/platform/catalog/` and the contract files under `agency-os/docs/AI_LEGO_Cognitive_Engineering_OS/methods/contracts/`) or a package id (the package list is `PK` in the supervisor page data; find it in `ai_lego/platform/assembler` or the kinds of the assembler). Reject unknown subjects. Required lessons: the loader exposes, for each package, the list of lesson ids the course for it requires (a field `course` in the lesson: `{package, order}`).
- Generator: `ai_lego/apps/cli/generate_lessons.py` drafts one lesson per tool from the tool's own page text and its example (read how the tool pages produce their text; reuse that function, do not copy), writes `state: draft` files, never overwrites an existing file, and prints a report. It makes NO model call. It runs only when the operator runs it; do not run it for all tools in this card: run it for three tools and commit those three files as the fixtures of your tests (their texts must read as plain Chinese, one idea per sentence; if the page text is not usable, `BLOCKED:` with the tool id).
- Rules in the lesson text (a test checks them with plain scans over every lesson file): never says a cited claim is true because it is cited (a lesson about sources teaches `有引註不等於是真的` and how to see independent origins: include exactly such a lesson, hand-written, id `sources-independent-origins`, state reviewed is NOT allowed: the operator reviews); no score/rank words; no demand that the learner reveal something vulnerable.
- Practice case file: `{id, version, title, text, source: {kind: publisher|source_card, name, checked_on}, place}`; the loader refuses a case without a recorded, checked source (`checked_on` a date). Provide three hand-written low-risk example cases from Taiwan and one international, each clearly marked `source.kind: publisher` with a real, public, neutral publisher you can name from general knowledge (a government statistics office release, a university notice); if you cannot name a real one, use `BLOCKED:` rather than inventing a source.
- A `draft` lesson is allowed to exist and be shown with the word 草稿; the loader exposes `reviewed_only()` for callers that must not use drafts (card 60 uses it).

## Files
`ai_lego/platform/lessons/__init__.py`, `ai_lego/platform/lessons/HISTORY.json`, `ai_lego/platform/lessons/lessons/*.yaml`, `ai_lego/platform/lessons/cases/*.yaml`, `ai_lego/apps/cli/generate_lessons.py`, `ai_lego/platform/rulesets/teach.py` (exposes the two rulesets through the existing discovery), `tests/unit/test_teach_content.py`, `docs/platform/STEP34_CHECKLIST.md` (create it with a TEACH section if it does not exist), `agency-os/reports/review-debt.md`.

## Acceptance
`tests/unit/test_teach_content.py`: loader reads every file, rejects (one broken temp copy each) an unknown subject, `minutes` over 5, a missing `state`, a case without `checked_on`, a text change without a version bump (against `HISTORY.json`), a lesson that declares `reviewed` but contains the word 草稿; the plain-text scans over every lesson; the generator makes the three fixtures deterministically (run twice: identical bytes) and never overwrites; the course lists are complete for every package with a lesson. Mutations to report: remove the fingerprint check -> red; accept `minutes: 9` -> red; accept a case without a source -> red; let the generator overwrite -> red.
