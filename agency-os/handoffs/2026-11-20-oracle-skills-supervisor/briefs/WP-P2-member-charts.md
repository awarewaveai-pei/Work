# P2 會員命盤與「我存的對象」

先讀：`COMMON-WP.md`、`ORACLE-WP-SPEC.md` §0（D2、D4）、§2-5、§2-6、§3 P2′ 列（`:81`）。外掛 `lobster-factory/packages/oracle-wp-plugin/`（整個讀完再動手；P1 已在 main `93f38797e`）。模型 Opus 5.5（個資：完成後 `critic` Deep，並做突變）。

## 目的
登入的會員能存自己的命盤，也能存別人的出生資料做私人合盤。不變量：一位會員的列只有他自己讀得到、改得到、刪得到；出生資料在資料庫與資料庫備份裡不以明文存在；會員被刪除時他的資料一起消失。

## 要做
照 SPEC `:81` 與 §2-5、§2-6，一項不少。另加第二批 RISKS 帶進來的兩項：
1. 設定頁的 `embed: cross-origin` 選項標「尚未支援」並不可選（現有引擎只允許同源框、沒有訊息協定；`README.md` 同步）。原有 `assets/embed.js` 留著不刪。
2. `assets/embed-same-origin.js` 的「結果出現時捲動」改認框內 `[data-aw-result]`（引擎卡 E5 正在加，屬性名已定）；找不到這個屬性的舊引擎時不捲，不退回用高度猜。

## 已知事實
- 金鑰：出生欄位用 libsodium secretbox；金鑰放 `wp-config.php` 常數，不進資料庫。P1 已有「私鑰可放 wp-config 常數」的做法（`AWORACLE_SITE_KEYPAIR`），加密金鑰照同一種放法，另一個常數名。金鑰不存在時：存檔功能停用並在後台顯示原因，不退回明文。
- REST 命名空間 `aworacle/v1`；登入加 nonce；未登入照常使用工具但不存，顯示「登入以儲存」。
- 「我存的對象」只屬於該會員，不與任何帳號關聯、不通知任何人（D4）。
- 既有資料：這是新表，沒有舊資料要遷；但外掛升級時要能在已啟用的站上建表（不只在啟用那一刻）。

## 驗收
- SPEC `:81` 的每一條都有測試：未登入 401；無 nonce 401；甲讀不到乙的列（讀、改、刪各一）；`wp db export` 的檔裡查不到測試用的明文出生日期字串；隱私匯出含兩類資料；刪除請求後兩表無該人資料；刪會員連動。
- 突變三次（各一個守衛）：拿掉擁有權檢查、拿掉 nonce 檢查、把加密改成明文寫入，指名測試變紅，還原變綠。
- 乾淨 WordPress（docker，資料放 `$env:TEMP`，一個 compose project，用完 `down -v`）實測一輪。
- `php -l`；PHPUnit 綠。

## 邊界
不做每日信與票（P3）；不做發佈（P4）；不改引擎。
