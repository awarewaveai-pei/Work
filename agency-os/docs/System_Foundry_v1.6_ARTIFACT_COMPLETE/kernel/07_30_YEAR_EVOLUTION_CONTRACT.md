# 30-Year Evolution Contract

Thirty-year engineering means preserving stable meaning while allowing implementation replacement.

## Stable assets
- domain language and invariants
- data semantics and lineage
- ownership
- public contracts and compatibility policy
- decision rationale
- migration history

## Replaceable assets
- framework
- runtime
- cloud/provider
- database engine when contractually isolated
- queue/transport
- deployment platform
- UI technology

## Required tests
Every material architecture must document:
1. five-year scale/evolution trigger
2. ten-year team/ownership evolution
3. thirty-year provider/framework replacement scenario
4. vendor-exit path
5. archival/data portability path
6. schema and contract evolution strategy

No design may claim "30-year ready" without passing the replacement tests in `assurance/30_YEAR_REPLACEMENT_TEST.md` and `assurance/VENDOR_EXIT_TEST.md`.
