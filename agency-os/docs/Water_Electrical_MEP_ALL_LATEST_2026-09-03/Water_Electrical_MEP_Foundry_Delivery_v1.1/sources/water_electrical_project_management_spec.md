# 水電工程營運管理系統需求規格書

> 版本：v1.0  
> 對象：10–25 人中型水電／機電工程包案公司  
> 系統型態：Web App / PWA  
> 核心目標：先解決現場派工，再逐步整合工程現場、材料採購、合約請款、成本損益與 AI 查詢。

---

## 1. 專案定位

本系統定位為一套適合中型水電／機電工程承包公司的內部營運管理平台，整合以下能力：

- 工程總覽
- 公司行事曆
- 人員派工
- LINE 派工通知
- Google Calendar 同步
- 圖面管理
- 工地照片
- 工作進度
- 工地日報
- 材料管理
- 廠商管理
- 採購管理
- 追加減
- 估驗請款
- 工程成本
- 工程毛利
- 角色與權限管理
- 手機版 PWA
- AI 查詢與摘要

系統採「完整架構一次設計、功能分階段啟用」的方式。

---

## 2. 系統核心原則

### 2.1 唯一正式資料來源

公司系統為正式資料來源（Source of Truth）。

- Google Calendar：用於員工個人行程同步
- LINE：用於即時通知、異動提醒與確認
- 公司系統：保存正式派工、工程、採購、成本與操作紀錄

Google Calendar 或 LINE 不應反向覆蓋公司正式派工資料。

### 2.2 權限從第一階段開始

權限不能等 ERP 模組完成後才補。

系統從 Phase 1 起即採：

- Role：角色
- Scope：資料範圍
- Permission：操作權限

例如：

> 王工務  
> 角色：工務  
> Scope：A案、B案  
> 權限：可派工、可看圖面、可上傳照片、不可看工程毛利。

### 2.3 Mobile First

現場人員以手機為主要操作裝置。

系統需支援：

- iPhone
- Android
- iPad
- Windows / macOS 瀏覽器
- PWA 加入手機主畫面

# 9. 派工管理

## 9.1 建立派工

派工欄位：

- 日期
- 開始時間
- 結束時間
- 工程
- 工地
- 工作內容
- 領班
- 員工
- 備註

例如：

```text
2026/09/05
07:30–17:00
桃園 XX 廠
B1 消防配管
領班：王先生
人員：大明、小華、阿宏
```

## 9.2 多人派工

單一派工可指派：

- 1 人
- 多人
- 整個班組

不得要求工務為同一工作分別建立多筆派工。

# 16. 派工確認

員工按下：

> 確認收到

系統記錄：

- 員工
- 派工 ID
- 確認時間
- 裝置資訊（選配）
- IP（選配）

工務畫面：

| 員工 | 通知 | 確認 |
|---|---|---|
| 王大明 | ✅ | ✅ 19:43 |
| 陳小華 | ✅ | ✅ 20:01 |
| 李志明 | ✅ | ⚠️ 未確認 |

派工異動後，原確認狀態必須失效並要求重新確認。

```text
桃園A案｜B1消防配管
```

## Event 地點

```text
桃園市○○區○○路
```

## Event 說明

```text
工程：桃園A案
工作：B1消防配管
領班：王先生
人員：王大明、陳小華、李志明

公司工程系統：
https://work.example.com/dispatch/123
```

同步規則：

```text
建立派工
→ Google Calendar 建立 Event

修改派工
→ 更新同一個 Event

取消派工
→ 取消或刪除 Event
```

不得因修改而重複建立 Event。

# 24. Phase 5：AI

AI 僅能查詢使用者本來有權限看到的資料。

## AI 功能

### AI 工地日報整理

輸入：

```text
今天四樓三個人做照明配管，完成八成，
缺一吋半盒接，明天繼續。
```

輸出：

```text
施工區域：4F
施工人數：3人
施工項目：照明配管
完成度：約80%
缺料：1.5吋盒接
明日工作：持續照明配管
```

### AI 查詢

例如：

# 33. 系統最終定位

系統正式定位：

> **水電工程營運管理平台**

第一階段解決：

> 人員、工程、派工、行事曆、LINE、Google Calendar
