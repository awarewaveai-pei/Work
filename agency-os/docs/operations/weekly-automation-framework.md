# Weekly Automation Framework — RETIRED (2026-05-30)

> **This machine-local framework was retired on 2026-05-30.** It ran as a Windows Task
> Scheduler job (`AgencyOS-WeeklyAutomation`) on a single desktop, had no cross-machine
> guarantee and no freshness watchdog, and silently stopped producing reports for 19 days
> (last output 2026-05-11) without anything surfacing the gap. See the retirement note in
> `agency-os/reports/weekly/README.md`.

## What replaced it

The two former weekly jobs were resolved as follows:

| Former job | New home | Why |
|------------|----------|-----|
| `weekly-system-review` (build gates + integrated status) | **Already covered** — `npm run validate` runs on every PR ([release-gate-main.yml](../../../.github/workflows/release-gate-main.yml)) and on push ([lobster-workflows-validate-main.yml](../../../.github/workflows/lobster-workflows-validate-main.yml)); the integrated status report is regenerated by `scripts/ao-close.ps1` every close-out. The weekly re-run was pure redundancy. | Build-gate regressions need *push-time* detection, not weekly. |
| `workflows-security-audit` (`npm run audit:workflows-security`) | **GitHub Actions weekly cron** — [.github/workflows/weekly-workflows-security-audit.yml](../../../.github/workflows/weekly-workflows-security-audit.yml) (Monday 01:30 UTC = 09:30 TPE). High/critical findings auto-open a `weekly-security-audit` + `needs-human-review` issue. | New CVEs appear against *unchanged* deps over time — a time-based scan is the correct model, and it is deterministic (no LLM needed → GHA, not a Claude routine). |

## Adding a future time-cadence job

Add a step or a new job to the GHA workflow above (git-tracked, machine-independent). Do **not**
reintroduce a machine-local Windows scheduled task for repo-level automation — that is the exact
anti-pattern this retirement removed.

## Still local (separate, not affected by this retirement)

- Monthly review (`AgencyOS-MonthlySystemReview`, `scripts/register-monthly-system-review-task.ps1`,
  `scripts/monthly-system-review.ps1`, `scripts/check-supabase-memory-monthly.ps1`) is still a
  machine-local scheduled task. It has the **same** machine-dependency defect and should be
  evaluated for the same treatment in a follow-up.
