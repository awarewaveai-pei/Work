# ADR-024 — Spec-on-demand, a cap on specification prose, one status SSOT per line of work, and the shape of verification (post-Phase-5 rule)

This ADR is the forward-looking half. It does not modify any mother document.
Related: `AI_LEGO_OS_Program_Plan_v1.md` §10 (the Phase 0–2 no-code rule this ADR complements, not repeals), §11 (Phase 5 EXIT GATE PASSED, local synthetic scope), §13 (change management); ADR-022, ADR-023 (the runtime landing and its follow-ups — the concrete evidence behind §Context); `docs/architecture/MACHINE_READABLE_SPEC_PLAN.md` (the Phase 3 build order this ADR stops extending by default); `tests/gen_spec_index.py` (the generated indexes §Decision 2 relies on).

## Context

The program's first five phases were, by design, specification before code: Program Plan §10 forbade production code, UI, DB schema and provider SDKs during Phase 0–2, and Phases 3–4 compiled the three mother documents into 55+ JSON-Schema files, 20+ ADRs, 5 method contracts, policy files and a 2,457-check golden suite before a single line of runtime existed. That produced real value once code arrived: the Phase 5 runtime (ADR-022, 2026-09-03) validates every emitted record against those schemas before it is persisted, and the same-day adversarial review found two real crypto/timing bugs precisely because the schemas made the expected behaviour checkable.

It also produced a cost model with no upper bound. Measured on the one day where both kinds of work happened (2026-09-04, ADR-023 follow-ups):

| Item | Substance | Justification prose around it |
|---|---|---|
| Three capability contracts | ~30 lines of YAML each | ~150 lines each (`description`, `compilation_decisions`, `verification`) |
| One new schema (`capability-resolution.schema.yaml`) | ~120 lines of shape | ~230 lines of prose |
| Runtime change | ~250 lines | status mirrored into 6 documents (ADR gate table, slice doc, Program Plan, MRSP, TASKS, WORKLOG, memory); one test-count bump alone needed 2 extra commits |
| Mother-document citations by line number | — | drifted twice in one day (`L724`→`L726`, `L1935`→`L1936`); older files cite pre-ADR-017 line numbers ~28 lines off |

Roughly 40–50% of the week's effort went to specification breadth built ahead of any consumer (289-method inventory with 5 contracts; jurisdiction / conflict-of-laws / entitlement / market-entry schemas with no runtime reader), to per-file essays, to multi-agent review of documents, and to keeping six status mirrors aligned. The specs that were consumed were consumed **once code existed to read them** — and were revised the moment it did (ADR-023 rewrote the capability story the day the runtime touched it). The five invariants the corpus exists for — fail-closed resolution, three-axis provenance, crypto-shred erasure, tenant-scoped isolation, no-skip state machine — are enforced by tests and schemas, not by prose.

## Decision

1. **Spec-on-demand (first-consumer rule).** From Phase 5 onward, a new schema, contract, policy or registry entry under the spec root is written **when a runtime change first needs it**, by the same change, in the same commit. A spec with no consumer is not written ahead of time. Existing spec files with no consumer are **not deleted**; they may be marked `status: DORMANT` (a doc-meta value, not a JSON-Schema keyword) by the first change that would otherwise have to edit them, and are revised when a consumer arrives. Program Plan §10's Phase 0–2 rule stands as history; this decision is its post-Phase-5 complement.
2. **A cap on specification prose, and section-anchored citations.**
   - A contract or schema file carries: `$id`/`title`/`status`, a `description` of at most ~15 lines, `source_of_truth_for` with **section** anchors (`MP §8.4`, `EC §83`), at most three `compilation_decisions` (one paragraph each), `open_questions` as one line each, and a `verification` block of at most ~10 lines. Anything longer is a sign the content is an ADR-level trade-off and belongs in an ADR.
   - Mother documents are cited by **section**, never by line number. `docs/architecture/MOTHER_DOC_SECTION_INDEX.md` (generated by `tests/gen_spec_index.py`, freshness enforced by golden check family 6) maps every heading to its current line, so a reader can still jump; `docs/architecture/SPEC_QUICKREF.md` (same generator) lists every schema's named shapes and `required` lists so a session can locate a shape without reading the file.
   - Existing files are **not** rewritten to the cap retroactively; the cap applies to new files and to sections a change touches.
3. **One status SSOT per line of work.** A line of work (e.g. the Phase 5 slice) has exactly one document that carries its live status and numbers (for the slice: `Projects/internal/cognitive-engineering-os/docs/PHASE5_RESEARCH_SLICE.md`). Every other place — ADR gate tables, Program Plan §11, MRSP, TASKS, memory — carries a **pointer** to it and, at most, a dated one-line summary that is allowed to be stale. Test counts, pass counts and similar numbers are not copied into pointer documents.
4. **The shape of verification.** For code: mutation tests (a deliberately broken guard turns a named test red, then is restored) are the primary evidence; one critic per commit, scoped by the tier rules in `.claude/commands/review.md`; multi-agent review only for auth / crypto / personal-data changes. For spec YAML and documents: the golden suite plus one written self-review; **no agents are spawned to review documents**. Reading and understanding is done by the main agent (see `agency-os/AGENTS.md` §Agent 扇出治理 for the repo-wide reading rule). This applies the repo's existing fan-out governance to this program rather than restating it.

## Alternatives rejected

- **Repeal Program Plan §10 retroactively.** It describes a phase that is over and that produced the schemas the runtime now validates against; rewriting history explains nothing and the Phase 5 exemption was already granted by the operator on 2026-08-30 (§11).
- **Keep writing the remaining ~285 method contracts and the dormant schemas to completion first.** That is the unbounded cost model this ADR ends; every spec written before its consumer was revised when the consumer arrived.
- **Delete the unconsumed spec files.** They are grounded transcriptions of mother-document text; deleting them destroys work that a future consumer would redo. Dormant is honest and reversible.
- **Apply the prose cap retroactively to all 55+ files.** A rewrite pass of that size is exactly the kind of work with no product-visible output this ADR is written to stop; the cap governs what is touched from now on.

## Consequences

- Positive: a new capability or method needed by the next slice costs one short file plus its fixtures, not a two-day authoring pass; a session finds a shape from the quick-ref instead of reading 900 lines; a number changes in one place.
- Positive: review effort scales with risk (auth/crypto/PII) rather than with file count, and the quota that reviews consume stays available for the reviews that matter (on 2026-09-04 both external oracles were exhausted by earlier fan-outs and the code review had to fall back to self-review).
- Negative: the corpus will contain files at two prose densities (pre-ADR-024 essays, post-ADR-024 short files). Accepted; `SPEC_QUICKREF.md` gives both the same one-line summary.
- Negative: `DORMANT` is a new doc-meta status value alongside `ACTIVE`/`PROVISIONAL`/`PARTIALLY_DEFINED`; the runtime's "registered" definition (ADR-023) already treats anything but `ACTIVE` as unresolved, so a DORMANT contract cannot be invoked by accident.
- Follow-ups: (a) `tests/run_golden_tests.py` check family 6 runs `gen_spec_index.py --check` (landed with this ADR); (b) the next slice (real speech-to-text + a local LLM producing coding suggestions, CLI only) is the first work item executed under this rule and is the test of whether the cap holds in practice; (c) if a DORMANT marking is ever needed, add the value to the doc-meta convention note in `MACHINE_READABLE_SPEC_PLAN.md` at that time, not before.

## Verification and rollback

Verification: `python tests/run_golden_tests.py` (check family 6 must report the generated indexes fresh); `python tests/gen_spec_index.py --check` exit 0. Rollback: `git revert` of the commit that lands this ADR, the generator and the two generated files; no runtime behaviour depends on them.
