# Codex Adversarial Review

Target: branch diff against a62739235
Verdict: needs-attention

No-ship: the new branch/release gate specs still permit a real gate bypass and introduce two release-policy references that are not actually enforceable from the repo’s visible rule sources.

Findings:
- [high] Merged branches can omit `risk_tier` and bypass the new R3/R4 gate checks (agency-os/docs/AI_LEGO_Cognitive_Engineering_OS/specs/workflow/branch.schema.yaml:195-210)
  `branch.required` only includes `branch_id` and `state`, even though `risk_tier` is described as required. The only enforcement of ADR-012’s extra gates is the later `if state=MERGED && risk_tier in [R3,R4]` block, so a producer can serialize an R3/R4 merge without `risk_tier` and the schema will accept it with no `gate_results`. That defeats the human-review and recovery-rehearsal controls this change is supposed to add.
  Recommendation: Make `risk_tier` required at least for `MERGE_REQUESTED`/`MERGED`/`ROLLED_BACK` states, and add a regression fixture where `state: MERGED` with missing `risk_tier` fails validation.
- [high] `release_gate_requirement` points to the mandatory-gate schema node, not the live rule instances (agency-os/docs/AI_LEGO_Cognitive_Engineering_OS/policies/ai-execution/release-policy.yaml:317-383)
  `gate_rules_source` and `scope.conditionally_required` both point at `ai-lego://policies/ai-execution/mandatory-gates.yaml#/mandatory_gate_rules`, but that node is only the array shape (`type`/`items`/`minItems`). The actual 2026-08-30 rule set lives under `grounded_rules.rules` in `mandatory-gates.yaml`. Any consumer that dereferences the URI to discover which high-risk gates are required will get no concrete gate IDs, so release gating either becomes dead code or depends on hidden out-of-band knowledge.
  Recommendation: Retarget these fields to a canonical data node that actually enumerates the active rules (`grounded_rules.rules` or a dedicated `active_rules` section), and add a test that dereferencing the URI yields the expected rule IDs.
- [high] The new `always_required` global gates depend on a producer that is not visible anywhere else in the repo (agency-os/docs/AI_LEGO_Cognitive_Engineering_OS/policies/ai-execution/release-policy.yaml:357-373)
  This change makes all 14 `gate_catalog.global` items mandatory for every release, but the only gate-emission path I could find in the repo is still `mandatory_gate_injection_trigger`, which fires only on `risk_tier IN [R3, R4]` (`risk-tier.schema.yaml:128-145`, `gate.schema.yaml:203-214`). I could not find any second low-risk/global gate producer. That leaves R0-R2 releases in a contradictory state: either they can never satisfy `always_required`, or implementations will silently skip the global gates despite this policy now claiming they are mandatory.
  Recommendation: Define and reference an explicit global-gate emission/recording path for every release, or narrow `always_required` until that producer exists; add an R1 release fixture that proves the chosen path.

Next steps:
- Require `risk_tier` in `branch.schema.yaml` wherever merge-state validation depends on it.
- Point release-policy at concrete mandatory-gate data, not the schema fragment.
- Resolve the low-risk/global gate production model before treating `release-policy.yaml` as `ACTIVE`.
