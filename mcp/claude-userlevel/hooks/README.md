# Governance Hooks (runner v2)

**English · [繁體中文](./README.zh-TW.md)**

All of Claude Code's mechanical gates run through **one runner** (`runner.js`) that dispatches to **pure rule modules** (`rules/*.js`) according to **one wiring manifest** (`rules.manifest.json`). The lifecycle plumbing every hook used to hand-roll — stdin read, JSON parse, session-ID derivation, flag files, fail-open error handling, exit codes — is implemented exactly once, in the runner and `lib/`.

```
hooks/
├── runner.js            # single entry: node runner.js <event>
├── rules.manifest.json  # SSOT: event → matcher → ordered rule names
├── rules/               # one file per rule: module.exports = { check(ctx) }
├── lib/
│   ├── shared.js        # SID derivation, tracker I/O, risk classifier, fail-open log
│   └── flags.js         # once-per-session flag files (atomic wx create)
├── ao-resume-on-prompt.ps1        # machine-level (Windows), wired directly in settings
└── post-push-trigger-deploy.ps1   # machine-level (Windows), wired directly in settings
```

## Structural guarantees

These hold for every rule because they live in the runner, not in per-rule discipline:

- **Fail-open, loudly.** A rule that crashes or fails to load can never block a tool call or take down sibling rules. The failure is printed to stderr *and* appended to `~/.claude/verify-gate-failures.log`.
- **exit 2 is the only block.** Rules return `{ block: [lines] }`; the runner aggregates every matching rule's verdict, prints all block messages together, then exits 2. Anything else passes through.
- **One SID scheme.** `lib/shared.js getSessionId()` (stdin `session_id` → `CLAUDE_CODE_SESSION_ID` → `CLAUDE_SESSION_ID` → sha1(cwd)) — the three divergent derivations of the legacy hooks are gone.
- **No hand-written counts.** The SessionStart banner derives rule/event counts from the manifest. If prose needs a number, derive it — drift-by-copy is how the old "15 total" description went stale.
- **Shell-wrap visibility.** The runner exposes `ctx.commandExpanded` with `bash -c "…"` / `sh -lc '…'` payloads unwrapped (depth 3), so command-scanning rules can't be bypassed by string-wrapping. The single-line `cd x && docker compose down` chain remains a documented pass (deliberate operator action).

## Rule API

```js
// rules/example.js
module.exports = {
  check(ctx) {
    // ctx: { event, payload, toolName, toolInput, command, commandExpanded,
    //        files, sid, cwd, shared, flags, manifest }
    if (!somethingWrong(ctx)) return null;      // pass
    return { warn: ['[Hook] heads-up …'] };     // stderr, non-blocking
    // or
    return { block: ['[Hook] BLOCKED: …'] };    // aggregate → exit 2
  },
};
```

Adding a gate = one file in `rules/` + one name in `rules.manifest.json` + one case in `tests/hooks/runner-parity.test.mjs`. Removing one = the reverse. Nothing else changes.

## Wiring (three consumers, one manifest)

| Environment | Wiring file | Command |
|---|---|---|
| Windows workstations (user-level) | `settings.template.json` → synced to `~/.claude/settings.json` | `node ~/.claude/hooks/runner.js <event>` |
| Plugin packaging | `hooks.json` | `node ${CLAUDE_PLUGIN_ROOT}/hooks/runner.js <event>` |
| Remote containers (Claude Code web) | `.claude/settings.local.json`, generated by `scripts/wire-remote-hooks.sh` (gitignored — a tracked copy would collide with the `~/.claude` junction on workstations) | `node "$CLAUDE_PROJECT_DIR/mcp/claude-userlevel/hooks/runner.js" <event>` |

The wiring files contain **no rule knowledge** — they cannot drift from each other. Which rules run where lives only in `rules.manifest.json`.

The two `.ps1` hooks stay wired directly in `settings.template.json`: they are Windows/machine-level automations (AO-RESUME trigger, post-push Trigger.dev deploy), not portable governance.

## Rules quick reference

Blocking gates (can exit 2): `dangerous-bash` (rm -rf, --no-verify), `branch-protection` (force-push to protected), `commit-quality` (staged debugger/secrets), `verify-gate-commit` (commit with unverified code), `high-risk-bash-warn` (docker down / prod rsync / migrate — ACK with a leading `# CONFIRMED-HIGH-RISK:` line), `sensitive-file-block` (.env/.pem/.key writes), `git-log-injector` (first Write/Edit shows last session's commits, once per session+day), `auto-repair-guard` + `file-path-router` (once-per-category pre-checks/routing), `config-protection` (linter configs), `large-file-warner` (≥2MB reads), `mcp-health` (circuit-breaker with backoff).

Non-blocking: `suggest-compact`, `log-error`, `audit-log`, `accumulator`+`batch-format` (Prettier+tsc at Stop), `design-quality`, `test-runner`, `code-change-tracker` (+ verify tracker), `agent-dispatch-log`, `check-console`, `cost-tracker`, `session-summary`, `verify-gate-stop`, `session-banner`.

Authoritative list: `rules.manifest.json`. Behavior spec: `tests/hooks/runner-parity.test.mjs`.

## Testing

```
bash scripts/test-hooks.sh
```

`tests/hooks/runner-core.test.mjs` covers the runner guarantees (dispatch, crash isolation, aggregation, fail-open) against fixture rules; `tests/hooks/runner-parity.test.mjs` covers every rule's verdict matrix against the real manifest, including the manifest↔rules completeness check (no missing rules, no orphans). Node ≥ 18, zero packages.

## History

v2 replaced 23 standalone hook files + 5 inline blockers (2026-07-02). The migration was strangler-style: the legacy behavior was locked by a 48-case suite first (`tests/hooks/legacy-behavior.test.mjs`, retired with the legacy files — see git history), then rules were ported with parity asserted case by case. Four legacy defects were fixed in the process, each locked by a test: the inline rm-rf and sensitive-file blockers read the wrong stdin field and never fired; `bash -c` wrapping bypassed high-risk-bash-warn; `log-error.sh` silently failed on a fresh HOME.
